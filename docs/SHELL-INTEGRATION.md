# 项目环境与终端集成

两项功能互相独立：项目环境让人工与 agent 使用相同的项目工具和业务变量；终端集成只提供目录、区域与实际 shell 返回码，UI 由终端负责。不是版本管理器、插件系统、历史数据库或输出录制器。

## 配置

在[用户配置](DESIGN.md#11-配置)中选择：

```toml
[shell]
project_env = "off"           # off（默认）| direnv | mise；二选一，显式启用
terminal_integration = "auto" # auto（默认）| off | on
```

配置切换后重新启动 nosh。不会因为找到了二进制、`.envrc` 或 `mise.toml` 就自动启用环境加载，也不自动运行 allow、trust、安装或下载命令。

`--norc` 只跳过 rc，仍使用显式 `project_env` 配置；`--safe` 同时关闭托管项目环境及 AI。`NOSH_DISABLE_AI=1` 只禁用 AI，不禁用人工项目环境或终端集成。非法 `project_env` 保持错误状态并阻断 agent，不静默改成 off；非法终端配置告警后关闭标记。

## 项目环境

### 支持的工具模式

| 后端 | 接入方式与范围 |
|---|---|
| direnv | `direnv export json` 的字符串赋值/null 删除差量，保留工具的授权和环境恢复上下文。真实场景验证版本为 **2.38.1** |
| mise | **2026.10.5** 的 `hook-env -s nu` CSV set/hide 差量；这里只读取数据，不运行 Nushell、不 eval 激活代码。使用 `ls --current --json` 检查工具是否可用 |
| mise 范围 | 已安装运行时的 PATH、业务变量及离开目录恢复；不执行激活别名、enter/leave/watch hooks、daemon 管理或自动安装 |
| shims / 显式 exec | 仍是普通用户命令，不被 nosh 改写或接管；它们不会把子进程环境写回共享 shell，其工具自身的安装/回退设置仍有效 |

mise 使用的差量和未信任标志是版本相关接口，因此其他版本明确报不支持，而不是猜测兼容。工具升级后应重启会话。direnv 和 mise 不共同管理一个会话；mise 官方也不支持两套环境钩子叠加。

环境工具使用**共享 shell 当前导出的变量和 cwd**，不是 nosh 启动时的旧进程环境。未导出的变量和父 shell 函数不会凭空传给外部工具。agent 的防分页、非交互等临时变量仍只在其命令范围内生效，环境刷新先于这些覆盖及权限分析。

加载仍可能运行用户已授权的项目代码。nosh 不自动授权项目；环境事务也不是文件、网络或其他副作用的回滚/沙箱。mise 的刷新子进程使用工具自身的 no-hooks、离线解析及禁止自动安装设置，这不是对任意项目脚本的网络隔离。

原生接入不接受对 `PROMPT_COMMAND`、`PS0`–`PS4`、`BASH_ENV`/`ENV` 等 shell 执行控制变量的修改；这些属于提示符/脚本配置，不是本接口支持的业务环境。明确报错而非把项目数据作为提示符回调在共享 shell 中执行。已有用户自定义 PS1 和 rc 保持原来的配置入口。

### 生效边界

| 入口 | 行为 |
|---|---|
| 人工交互 | 真实提示符周期启动一次刷新；计算期间可以编辑，就绪时在编辑器安全点原子应用并更新输入/补全上下文，保留草稿。提交时仍未完成则等待结果或取消，再进行分类；按键、菜单和重绘不启动新加载 |
| 同会话 agent | 任务和 exec 边界刷新，在命令解析/风险评估/审批前确定环境；同一批工具调用间也生效。人工审批期间环境改变会重新评估 |
| `cd project && command` | **不在这一条程序内部刷新**；`command` 使用本条开始时的托管环境。分成两次输入或工具调用时，下一次执行会刷新 |
| 配置在编辑期间变化 | 下一约定边界检查；不实时监听文件，不承诺冻结外部文件系统或消除执行中的所有外部竞争 |
| 外部 `nosh -a` | 无管道附件时按显式配置初始化；新 shell 继承导出环境，不重跑全部 rc，不继承父 shell 未导出状态 |
| `-s`、Generate/Fix/Next | 不因请求建议调用环境工具或项目脚本；只读取已有会话/继承环境 |
| 管道附件的 `-a` | 保持只读工具边界，不执行环境初始化 |
| `-c`、脚本、普通 stdin | 不注入交互环境刷新 |
| 后台作业、外部交互程序 | 继承启动时环境；不会被 nosh 动态改写内部状态 |
| `agent.restore_cwd` | 恢复目录后使就绪状态失效，下一边界重新加载，不能沿用任务结束目录的环境 |

不拆分或重写 Bash 程序；用户程序自身的赋值、函数、子 shell 和管道语义不变。

### 失败、取消与恢复

- 未启用、待刷新、加载中、就绪与失败状态分开。失败/取消/超限/非法数据不应用部分差量，保留加载前环境，并报告上次验证的项目。
- **人工可继续修复或离开目录；agent 不使用已知失效环境执行。** 环境失败不伪造一个已经执行过的命令、退出码或 CommandAssist 修复目标。
- direnv 失败时也可能输出差量；mise 未 trust 或缺工具时也可能成功退出。不能用“有输出”或 exit 0 单独判断就绪。
- 人工修复授权、工具或配置后，下一个真实提示符允许重试。direnv 在失败后仅返回空差量时仍保留失败状态，可在检查配置后显式运行 `direnv reload`。离开失败目录后重新判定。
- 取消使迟到结果失效；未回收任务仍占据额度。没有后台无限重试或不断替换 worker 的降级。
- 提交输入后若正在等待环境，Ctrl-C 取消等待并保留草稿，**不会继续执行这条刚取消的输入**。普通加载失败仍按人工可继续的规则处理。
- 错误去重，不打印整个环境、差量值或原始工具输出到提示符、终端元数据或模型上下文。工具失败会指出后端和失败类别/退出码。

### 已有初始化脚本

不要让 nosh 内建刷新和同类 rc hook 双重接管。发现当前 shell 的已知 direnv/mise 激活函数时，内建刷新报告配置冲突并阻断 agent；不会自动删除用户函数或改写 rc。可以调整自己的 rc，或用 `nosh --norc` 配合显式后端配置。

`mise activate bash --no-hook-env` 会保留包装函数但明确关闭自动钩子，这种情况允许原生接入；若仍在 `PROMPT_COMMAND`、`precmd_functions` 或 `chpwd_functions` 中注册了已知 mise 钩子，则仍视为冲突。

`project_env = "off"` 只关闭内建接入，不禁止用户自己加载脚本。任意自定义 rc、`PROMPT_COMMAND` 或第三方脚本仍是用户代码，不因此获得本功能的超时与恢复保证。nosh 不会在 agent 每一步重放整个 `PROMPT_COMMAND`。

### 资源预算

| 项目 | 当前上限 |
|---|---|
| 活跃/待回收环境任务 | 每个 shell 一个；原任务回收前不能启动替代任务，无排队历史 |
| 整次刷新等待预算 | 5 秒，包含工具查询；**不是**底层任务已经停止的证明 |
| 导出快照、输出差量、环境提交候选 | 各 4 MiB；变量数量 16,384 |
| 工具 stderr | 64 KiB，超限失败，不直接输出原文 |
| 每轮管道读取 | 每个流最多 64 KiB，轮询取消与截止时间 |
| 退出清理宽限 | 最多 250 毫秒；不能无限等待，未完成会明确报告 |

外部执行和进程回收不持共享 shell 锁；仅快照与提交使用短锁，提交前验证上下文代次及 readonly/特殊变量。按既有进程所有权机制管理本功能启动的子进程和后代，不选择用户的其他后台作业。

这些数字是资源预算，不是性能达标声明。开发验证使用 Ubuntu WSL2、隔离 HOME、两个预置 Python venv 和固定工具版本；真实工具测试输出每次刷新耗时。不能据此推断网络挂载、任意环境脚本或所有主机的性能。

## 通用终端协议

只实现一套 **OSC 7 + OSC 133**：

| 序列 | 内容 |
|---|---|
| OSC 7 | 正确编码的当前目录 file URI |
| OSC 133 A/B | 提示符/输入边界，由锁定 Reedline 标记设施提供 |
| OSC 133 C/D | 实际执行区域及其 shell 退出码，由 nosh 的执行生命周期提供 |

普通 shell 命令报告实际返回码。AI 请求是一个外层活动区域，多次工具与流式输出不各自生成用户命令；结束时不附 shell 返回码，不把最后一个工具的结果或 exit 0 当作 AI 目标完成。

空输入、取消、纠错回填、菜单和建议采用没有真实 shell 执行时，不生成带退出码的完成记录。用户命令失败后进入 AI，先结束用户命令区域，再组织 AI 输出。后台并发输出不保证按字节精准归属。

### 简单自动发现

- `auto` 在 REPL 初始化时检查输入 TTY、**分别检查 stdout/stderr** 的终端能力、TERM 和已知宿主提示。目前自动识别 `TERM_PROGRAM=WezTerm` 或 `vscode`。
- 未知/缺失宿主提示、dumb/unknown TERM、tmux/screen 或已知当前 shell 外部集成时保守关闭。仅 `TERM=xterm-256color` 不能证明协议支持。
- `on` 可以为其他已知兼容终端手动启用；仍不能绕过非交互、重定向或 dumb 的流向保护。`off` 选择不发送内建元数据。
- 不运行查询子进程、不向终端发探测请求、不每次绘制做身份查询。宿主环境变量只是显示兼容提示，不是信任来源。
- Reedline 在 stderr 绘制提示符，所以 nosh 自己的标记也写 stderr，并且要求 stdout/stderr 都适用。不污染重定向、`-s` 或 JSON 输出。`NO_COLOR` 不关闭结构标记。

终端已有集成脚本与内建标记应选择一个所有者。自动检测只能退让于已知当前 shell 的集成函数，不能识别所有任意脚本；复杂配置使用 `off`。不会因为继承一个宿主变量就假装当前 shell 已加载集成。

### 兼容边界

WezTerm 明确支持 OSC 7/133；VS Code 支持其基础能力，但不等同于 633 的完整 Rich 集成。具体目录继承、导航、选择和状态 UI 由终端版本与配置决定。不支持协议的宿主仍是普通终端，不由 nosh 补做 UI。

| 实际验收环境 | 已确认范围 |
|---|---|
| Linux WezTerm `20240203-110809-5046fc22`，Ubuntu WSLg/X11、直接 Linux PTY，`auto` | 包含空格的 cwd 更新与新分屏继承；真实提示符/输入/输出区域；调用命令导航；依据语义区域进行 GUI 选择，完整取得两行输出 |
| Windows VS Code `1.140.0` + WSL，关闭其脚本注入、使用通用协议 | 确认 cwd 更新和实际成功/失败返回码；未将此组合的分屏继承、完整区域选择或 Rich 集成列为已验收能力 |

Windows 宿主经 WSL/ConPTY、其他终端和 macOS 的完整 UI 组合需分别确认，不能从协议名称或 Linux 的结果推断全部可用。上述 GUI 验收使用终端实际状态和选择内容，不只检查转义字节。

首版不做 OSC 633/1337、完整命令行/环境上报、nonce、tmux 转发、嵌套 shell 专项适配或终端插件。路径中的中文、空格、分号、控制字节及非 UTF-8 Unix 文件名字节按 URI 编码，不把它们直接插进控制序列。

元数据不是审批依据或可信历史。用户程序的原始输出照常透传；本功能不采集密码、交互 stdin 或持久保存完整输出，不改变[输出采集](OUTPUT-CAPTURE.md)及历史策略。

## 开发验证

正常回归包含环境数据/故障夹具、同批 agent 工具切目录、权限分析前刷新、真实 PTY 的普通/AI/取消/多行区域，以及独立流向降级。固定工具集成测试另行显式运行，不在产品运行时安装工具：

```bash
NOSH_TEST_DIRENV=/absolute/path/to/direnv \
NOSH_TEST_MISE=/absolute/path/to/mise \
cargo test -p nosh-shell --test project_env --locked -- --include-ignored --show-output
```

真实工具用例需要 Python 3 的 venv 模块，使用隔离临时 HOME/配置和人工测试授权，不读取或修改用户实际的 direnv/mise 项目配置。协议/PTY 自动化不能单独作为所有宿主 UI 已验收的声明。
