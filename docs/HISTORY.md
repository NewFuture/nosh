# 历史输入与命令保存

适用于 Linux/WSL、macOS 的 nosh 交互 shell。历史用于找回输入，不是副作用审计、终端录制或 AI 对话恢复；记录存在本身不证明执行成功，已记录的退出码只表示 Shell 返回的结果。

## 使用

在普通编辑中可进入历史导航的位置按 ↑/↓，或使用 Ctrl+R／配置的历史搜索动作，打开同一个上下文历史候选菜单，包含持久命令及本次内存输入。唤出菜单不立即替换草稿。它复用 `#` 命令和普通补全的候选列表，统一显示在命令输入框下方，使用相同的主题、选中样式和滚动布局。筛选直接使用原来的命令输入框和提示符，不新增“查找”输入框。普通输入不会自动打开菜单，多行光标移动、选区、Vi 待完成操作和补全菜单仍保留自己的输入控制。

| 历史菜单内操作 | 行为 |
|---|---|
| 输入、退格、粘贴 | 直接修改命令输入框中的筛选文字，按原文子串更新候选；打开前的草稿另存以便取消恢复 |
| ↑ | 向上选择更早的记录，必要时继续读取较早页；首次唤出只定位最近项，不额外跳过一条 |
| ↓ | 向下返回更新的记录；候选由旧到新排列，最近项在底部，到整个数据集边界后不循环 |
| Ctrl+R | 全部 ↔ 同项目；保留查询和所在历史位置，仍匹配的选中记录跨页也保持不变；该位置之前没有匹配时回到新范围的最近结果 |
| 左 / 右方向键 | 移动查询光标，不隐式回填候选 |
| Tab / Enter | 有匹配时回填选中项；确认无匹配时关闭菜单并保留当前输入和光标。两者都不执行，返回普通编辑后再按 Enter 才提交；默认提示只显示 Tab |
| Esc / Ctrl+G | 取消并恢复原草稿、光标、选区和发起模式 |
| Ctrl+C | 取消整份输入，沿用 shell 的保底行为 |

每次独立打开默认回到“全部”，保留输入框现有文字和光标位置作为筛选起点；导航候选不覆盖输入文字。列表最多显示 8 条候选，自动滚动到选中项，状态栏退让时的说明另计。空查询优先定位本次最近输入，本次还没有输入时使用已有命令。所有历史确认动作都只回填，不运行命令、切换目录或调用 AI；返回普通编辑后才能另行提交或请求建议。取消会恢复打开前的编辑与撤销/重做状态；回填是一笔可撤销编辑，不把中途筛选文字混入原草稿的撤销记录。

每条候选只保留必要的次数、执行结果及例外来源：普通命令不标注“命令／本次”，已确认属于当前工作树的记录不逐行标“本项目”。其它工作树显示 `其它:路径`，来源未知或工作树识别失败不冒充本项目；手动、提问·内存、建议·内存保留类型标记。选中记录的具体输入目录显示在状态栏，未能显示时沿用候选区兜底。

当前可用历史中连续重复的命令折叠为一个候选，附上 `xN`，例如 `ls  x4 成功`。只有完整原文、记录类型、会话、输入目录和工作树都相同时才合并；空白、多行或上下文不同仍是不同输入。中间夹有其它可用输入就分组，即使该输入被查询词或项目范围过滤掉也不合并两侧记录；提问和建议请求不折叠。

一组取最近一条真实记录作为代表，↑/↓ 按组选择；跨分页的大组也只占一项。次数在后台查询确认后显示，缓存查询中不猜测完整次数。`xN` 只是显示信息，不参与筛选、灰色预览或回填；数据库、`history`、`fc` 和文本导出仍保留每条原始记录，不合并、不删历史。存储不可用时只对可用缓存折叠，并保留结果不完整的错误提示。

执行结果不同的连续命令仍可折叠，但分别显示成功、失败和未知次数，例如 `x4 失败1 成功3`，不以最近一次结果代表整组。整组同为成功、失败或未知时只标一次状态，例如 `x4 未知`，不再重复写“未知4”；整组失败并不代表每次退出码相同。结果标记同样只属于显示，不会写入预览或回填内容。

当前选中项使用普通行内建议的灰色／主题弱提示样式显示在原输入框内，不是一次编辑：空查询预览整条输入，前缀匹配补出剩余部分，中间匹配在筛选词后用 ` -> ` 展示替换预览。筛选词保持正常颜色，光标仍属于真实查询；↑/↓ 只更新选择和预览，Tab／Enter 才回填完整原文，左右键仍只移动查询光标。未确认候选、无匹配或无有效选中项时不显示预览。

预览只占查询末尾在当前光标行的剩余空间，过长内容裁剪，多行和控制字符转为可见标记；末尾不在当前可见输入行时退让给输入和候选列表。无颜色模式保留纯文本预览与相同的回填边界。预览不进入编辑缓冲、撤销记录、命令历史或命令提交内容，也不单独触发历史或 AI 查询。

筛选草稿使用插入式文字编辑，沿用主输入框的默认移动、选区、词删除及撤销/重做快捷键；默认情况下，Vi 普通态进入后字母仍用于筛选，不作为 Vi 命令。Home/End、Ctrl+A/E 移到当前行首尾，Ctrl+Home/End 移到整个草稿首尾；Ctrl+U 只剪切光标之前的输入，保留后面的文字。可配置的文字编辑动作沿用已有的公共／模式配置，并可在 `history_search` 作用域单独改键或解绑。搜索内的撤销/重做只操作筛选草稿，Esc 仍恢复进入前的完整编辑状态。

无匹配时 Tab／Enter 返回普通编辑，当前筛选文字成为可继续编辑的草稿，并可撤销回打开前的输入；这与 Esc 恢复原稿不同。查询尚未完成、失败或选中项失效不视为无匹配，Tab／Enter 不因此退出，仍可使用 Esc 取消。

历史回填的输入不自动展开为命令缩写；搜索中粘贴后因无匹配退出，草稿仍保留粘贴来源。取消搜索恢复原草稿的缩写意图及编辑状态。

历史搜索中的 Tab 只回填或退出，不导航、不切范围、不补全或调用 AI，也不插入制表符；Shift+Tab 默认不绑定。Enter 保留兼容回填，提示优先使用 Tab；改键或解绑后只显示实际有效的主接受键。普通补全和 `#` 菜单中的 Tab 操作保持不变。

范围、查询/错误状态、选中记录的输入目录和按键提示优先复用提示符上方的状态栏，不再重复查询文字或整组菜单说明。候选区只标必要的结果和例外类型、来源；状态栏关闭、空间不足或随长输入滚出可见区时，只把未显示的必要信息放回候选区。窄终端会缩短预览，长命令的匹配词落在截断区域时展示匹配处的上下文，路径保留可辨认的尾部；多行内容以换行标记提示。显示裁剪不改变回填/提交的原文。历史不启用补全的唯一候选自动回填或无结果 AI 兜底。

磁盘查询在后台完成，匹配的热缓存记录可以明确选择。较早历史分页查询；查询中、无匹配、存储不可用分别提示。存储失败时，可信的内存命令和提问仍可回填，同时明确提示检索不完整或保存失败。接受时核对稳定身份与完整输入原文，不只比较 ID；次数、结果及来源说明的刷新不改变回填身份。到达分页边界后的缓存也需重新确认，查询中不误报为候选已经改变。异步变化不能把另一条输入悄悄替换成本次接受结果。后台刷新使原选中项消失时，需要重新导航选择。

## 范围

“全部”是当前历史数据集中的持久命令和本次可用的内存输入，不是读取所有历史文件，也不包含其它 shell 的提问。

“同项目”按输入时识别的 **Git 工作树根**过滤，包含其子目录，不合并共享仓库的其它工作树。嵌套的 Git 标记形成独立边界；不以 manifest 根、仓库名或远端 URL 代替工作树。

工作树标记在输入上下文更新时读取，搜索按键不运行 git 或扫描目录。非 Git 目录和识别失败有不同提示；识别失败在全部范围中也会提示，不把无法判断的来源标成“其它项目”。同项目不可用时明确保留全部范围，不把全局结果标为同项目。

路径按当时的工作树信息保存。目录移动后不自动合并旧路径，手动添加项缺少目录时保持未知；这些记录仍可在全部范围查找。检索来源提示不意味着恢复原来的 cwd、环境或权限。

## 记录哪些内容

| 内容 | 策略 |
|---|---|
| 用户提交的普通 shell 命令 | 允许记录时写入 SQLite；保留多行文本和输入时目录/工作树 |
| 显式提问、自然语言 AI 路由、`#fix` | 仅在本次 shell 内存中召回 |
| 真人通过非空 F2 / Tab 兜底发起的建议请求 | 仅内存；回填后可用 F2 再次请求建议 |
| 自动 Fix/Next、模型回复、Agent 工具调用 | 不自动加入该输入历史 |
| 未发送草稿、搜索词、候选预览、取消的 guard 操作、纠错待确认原文 | 不新增持久记录；纠正文本在真正提交后按实际入口记录 |
| `#help` 等管理输入 | 不作为持久 shell 命令记录 |
| `history -s` | 标为“手动”，不补造执行目录、结果或 AI 来源 |

提问只保存用户输入，不保存回答、模型上下文、附件或输出正文。重新提问使用当前上下文，不恢复旧对话、失败记录或授权。建议请求只回填后，编辑器仍按当前入口工作：F2 请求建议，Enter 按正常输入路由提交。

`#clear` 仍表示开始新 AI 对话，不删除本次提问历史。清理输入历史使用下面的历史操作。

## 执行状态

真人提交并实际交给 Shell 的命令，开始执行时绑定原记录身份，完成后保存退出码：`0` 显示“成功”，非零显示“失败(退出码)”。它是整条输入的 Shell 结果；管道、复合命令和后台启动采用 Shell 自身的退出状态语义，不单独追踪其中每个进程或后台任务的最终结果。

- 手动添加和没有取得结束结果的记录显示“未知”，不默认算成功或失败。
- Ctrl+C 等路径返回的实际退出码照实记录；例如 `130` 会保留为 `130`，不只凭这个数字猜测中断原因。
- 提问和建议请求没有 Shell 执行状态，不显示命令的成功/失败标记，也不因此落盘。
- `fc` 重放绑定新执行记录并保存它自己的结果；被忽略的输入不会把结果写到上一条记录。清空、删除或改写记录后，迟到结果不会重建记录或附到另一条命令上。
- 完成通知通过同一后台存储队列更新，保存失败会提示，不能改变命令本身的退出结果。刷新仍保留同一原文的已知缓存结果，但磁盘上已有的结果优先；改写原文不会沿用旧结果。执行期间切换历史目标导致结果未保存时明确报错，不跨目标写入或复制记录。

首发数据库结构包含可空退出码，不提供旧格式导入或迁移。显式文本导出只含命令和时间边界，不导出退出码。

## 存储与 HISTFILE

命令数据库是 **`<HISTFILE>.nosh.sqlite3`**。没有显式配置时，`HISTFILE` 取 nosh 状态目录下的 `shell_history`；`HISTFILE` 本身仅作为显式文本导出路径，不会被改写成数据库。

- SQLite 是唯一的命令持久来源，采用事务增量写入、稳定记录身份和顺序索引；退出不覆盖整份会话快照。
- 启动、刷新和切换 `HISTFILE` 都不读取已有文本文件；环境变量与 rc 中的 `HISTFILE` 只选择当前存储位置。
- 表、索引和格式标记在同一初始化事务中创建。目标路径与保留策略一起配置，同时修改它们不会意外裁剪原数据库。
- `HISTFILE` 为空、unset 或 `/dev/null` 时停止新持久化；当前可用的内存记录不因此自动删除。之后更换 HISTFILE 不把旧快照自动复制到新数据库。
- 新数据库和文本导出使用私有文件权限；已有文件及其父目录仍受用户的文件系统权限配置影响。

保存失败会明确提示，已接受的命令可暂留内存，不改变真实命令退出结果。迟到的保存错误通过输入所有者通知，不让后台线程直接破坏当前终端草稿。

## history / fc

这些内建命令看到同一历史服务的**命令视图**，不包含临时提问。因此 `history -w`、`history -a` 和 `fc` 不会把提问当作命令导出或执行。

| 操作 | 当前语义 |
|---|---|
| `history [n]` / `fc -l` | 显示当前命令视图；面板可进一步搜索数据库中的较早记录 |
| `history -s ...` | 添加手动命令文本，目录/工作树未知；不是一次真实执行 |
| `history -d offset` | 按当前命令视图定位稳定身份并删除；其它窗口旧缓存不会将其重新保存 |
| `history -c` | 清除本会话已知的持久历史快照及本次内存历史；快照之后其它会话的新记录不追删 |
| `history -n` | 从当前 nosh 数据库刷新命令视图，不重放插入事件 |
| `history -a [file]` | 向文本交换文件追加尚未导出的当前会话命令 |
| `history -w [file]` | 用当前命令视图替换指定文本交换文件；不是覆盖 SQLite |
| `fc -s ...` | 按历史规格替换并重新执行命令；越界编号、递归重放明确拒绝，不回退执行另一条命令；保留真实输入目录和忽略策略 |

文本导出使用 Bash 风格时间戳分隔，保留输入原文；未知时间用零标记。文本不作为备份恢复格式，SQLite 才是完整原文和执行结果的权威保存。

`history -n` 的显式文本文件参数、`history -r/-p`、`fc` 外部编辑器模式仍明确报告不支持，不返回假成功。文本导出拒绝覆盖活动数据库、其日志以及已识别的 SQLite 文件。

清理、目录过滤和逻辑删除不保证磁盘内容不可恢复；WAL、备份、文件系统快照和已有交换文件须分别处理。超时表示操作尚未确认，不表示底层工作已经停止；迟到的清理结果不会删除请求后新增的本次提问。

## 忽略规则与资源边界

原始输入在 trim/规范化之前判断记录策略。`set +o history`、`HISTSIZE=0` 停止常规输入记录；`HISTCONTROL` 的 `ignorespace`、`ignoredups`、`ignoreboth`、`erasedups` 以及 `HISTIGNORE` 的 shell 模式/`&` 按命令视图执行。无效忽略规则明确提示并不记录该输入；命令仍可执行。显式手动添加是独立操作，不通过按内容猜测“是不是秘密”。

`erasedups` 将当前命令视图中的重复记录与新输入合为一次后台事务，不逐条同步等待删除。保存失败或等待超时仍保留新输入的内存记录；数据库删除与新增同时提交，新增失败不会仅删掉旧记录。

| 资源 | 当前边界 |
|---|---|
| 命令热缓存 / 提问缓存 | 各最多 1,000 条、8 MiB 文本；提问被容量淘汰时提示 |
| 命令内建视图 | 不超过正整数 HISTSIZE 和热缓存边界；更早的持久命令通过面板搜索 |
| 单条记录 / 查询 | 256 KiB；超限明确拒绝记录或搜索，不截断成另一条可执行命令 |
| 查询页 | 最多 64 个候选组、1 MiB 代表命令文本；计数和连续性判断在后台流式完成 |
| 单次磁盘检索 | 至多处理 10,000 条输入、16 MiB 命令原文、250 ms；预算耗尽明确提示结果不完整，未完成的重复组不发布次数，必要时只展示缓存候选 |
| 工作队列 | 128 项；不按每次输入创建新线程 |
| 显式存储确认 | 有界等待；超时报告未确认，不伪称底层 I/O 已终止 |

非负整数 `HISTFILESIZE` 限制 SQLite 保留的命令条数；零不写入新的命令正文。未设置或负值不自动设定保留期限。缓存数量和持久保留量是不同概念，截短缓存不会把整库截短。

工作线程隔离数据库查询与输入，过期查询可取消；SQLite writer、文件系统 I/O 和工作树标记读取仍有实际成本，不承诺网络挂载或不可中断 I/O 一定即时完成。无结果不触发 AI，也不自动扩大查询范围。

检索预算耗尽不代表没有匹配；即使没有可用候选，也不将 Enter 当作已确认无匹配退出。预算按实际扫描量计算，不因筛选后只有少数候选而继续无限扫描。

这里的“不落盘”只针对新历史通道。既有显式 `NOSH_EVAL_TRACE`、工具输出日志、最近输出槽和本地 `NoRedact` 策略不改变；也不宣称操作系统换页或崩溃转储全局无痕。
