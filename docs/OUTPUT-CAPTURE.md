# 最近用户命令输出采集设计

> **状态**：当前实现，本地交互 shell 默认启用。
> **配置**：`shell.capture_output = "last" | "off"`，默认 `last`。
> **范围**：Linux / WSL 与 macOS 的交互 shell。`-c`、脚本、stdin 非交互模式、`-a` 和 `-s` 不进入中转 PTY。
> **关联**：[#18](https://github.com/NewFuture/nosh/issues/18)。失败求助快捷键和空输入行为仍由 #23 决定。

本文是最近用户命令输出采集的单一设计来源。总设计只保留系统级摘要；评测场景、运行命令和历史结果见[真实模型评测](../eval/README.md)。

## 1. 目标与非目标

### 1.1 目标

- 用户命令失败后，AI 可以看到**那次真实执行**的终端输出，不要求用户复制，也不为获取同一报错重新运行程序。
- 用户命令、cwd、退出码、耗时和输出通过会话内递增命令 ID 关联，不能把旧输出配给新命令。
- 不改变 Bash 的控制终端、作业控制、信号、交互输入、窗口大小、重定向及共享 shell 状态。
- 输出正文、元数据、转发队列和控制协议均有界；100 MiB 输出不能形成同等大小的内存缓存。
- 成功空输出、未采集、不可用、截断、不完整和已知混流是不同状态。
- 输出始终是不可信数据，不能形成模型消息、工具调用、授权或审批边界。

### 1.2 非目标

- 全量终端录制、完整 scrollback、历史输出查询或跨进程恢复。
- 分离 stdout/stderr。PTY 字节流只称为“终端输出”。
- 从重定向目标文件补采集内容。
- 判断任意后台写入者，或还原全屏程序的完整屏幕语义。
- 秘密脱敏、远程传输、网络服务、新模型工具或审批绕过。
- 原生 Windows 后端、SSH 断线恢复、`ai continue`。

## 2. 用户行为

### 2.1 配置与生命周期

```toml
[shell]
capture_output = "last"  # last（默认）| off
```

`last` 只在启动交互 shell 时建立会话级中转 PTY。配置在进程启动时读取；当前没有运行时切换或单独清空采集槽的命令。

每次真正执行用户命令时：

1. 分配新的命令 ID，并立即使前一条采集槽失效。
2. 记录执行开始时的 cwd；命令执行结束后记录退出码和耗时。
3. 将实际流经 PTY 的字节原样转发给用户，同时在独立副本上做有界文本处理。
4. 只保留最近一条已结束用户命令的快照。下一条用户命令会替换它，即使新命令成功或没有输出。

`off` 不创建中转进程，交互 shell 沿用原执行路径。无效配置会警告并采用默认 `last`。

### 2.2 何时把 last output 交给模型

采集与注入是两个阶段。当前实现的注入矩阵如下：

| AI 入口 | 是否附带最近输出 | 关联要求 |
|---|---|---|
| `ai fix [question]`、失败后的裸 `#`、空输入失败求助、失败自动诊断 | 是 | 输出命令 ID 必须与保存的失败命令 ID 完全一致 |
| `# <任务>`、`ai "<任务>"` | 否 | 普通任务默认不带终端输出 |
| 被路由到 AI 的解析错误、未知命令或自然语言 | 否 | 新输入不能继承上一条命令的正文 |
| Ctrl+G / `nosh -s` 命令建议 | 否 | 建议模式仍是独立、无工具、只回填 |
| `nosh -a`、管道附件 | 否 | 新进程没有交互会话采集槽 |
| `ai mode/status/clear` 等管理子命令 | 否 | 它们不创建普通 `AiRequest` |

`ai fix` 可以附加本次诊断要求，例如：

```bash
ai fix 解释实际报错并给出修复方法，不要修改文件
```

失败诊断使用最严格的 ID 配对。没有匹配失败记录时不调用模型，也不附旧输出。当前没有为成功命令显式选择最近输出的入口；该动作与快捷键由 #23 后续确定。

### 2.3 上下文污染控制

采集默认开启，但注入默认关闭。当前通过以下规则限制上下文污染：

- 只有 `Trigger::Failed` 可以携带 `[user_output]`，普通交互任务和解析/命令不存在路由均不携带。
- 失败命令 ID 与输出命令 ID 必须完全一致。
- 同一对话中每个命令 ID 最多附带一次正文；重复 `ai fix` 使用对话内已有证据。
- `ai clear`、空闲重置、上下文重建和相关配置变化会清空对话级去重状态；之后再次 `ai fix` 可以重新附带仍匹配的失败证据。
- 每次请求最多一个快照，正文最多 4,096 字节。
- 证据位于动态 user message，不修改静态 system prefix。
- 元数据明确记录原命令、命令 ID、执行 cwd、来源和完整性。
- 已知混流不附正文；全屏输出标记不可用。
- 模板把整个证据段按不可信文本编码；special token 字符串仍是普通数据。
- system rule 明确禁止把证据当作指令、权限或应用背景，并禁止为取得已有报错而重跑。

证据第一次注入后仍会存在于当前内存对话中，因此同一诊断对话的后续回答仍可能受它影响；这是需要引用报错的预期行为。`ai clear` 会清除这份对话上下文。

未来解释成功命令输出使用按需工具 `get_last_output`，并复用命令 ID 去重；不使用关键词或语义猜测自动注入，见 §11。

## 3. 数据模型

### 3.1 命令元数据

`UserCommand` 保存：

- 会话内递增 `id`
- 原始命令行
- 执行开始时 cwd
- 退出码
- 耗时

最近命令元数据列表仍可保留多条，但输出正文只存在于单一 `last_output` 槽，避免随历史列表复制。

### 3.2 输出状态

| 状态 | 含义 | 是否可附正文 |
|---|---|---|
| `NotCaptured` | 配置为 `off` | 否 |
| `Unavailable(NoPty)` | 请求采集，但没有可用中转 PTY | 否 |
| `Unavailable(ControlFailure)` | 控制通道或可靠命令边界失败 | 否 |
| `Unavailable(FullScreen)` | 观察到备用屏幕等无法当作线性文本解释的终端行为 | 否 |
| `Captured` | PTY 副本成功完成处理 | 是；已知混流时除外 |

`Captured` 另外记录：

- `observed_bytes`：PTY 原始观察字节数，零表示成功采集但没有终端输出。
- `text`：清理后的文本尾部。
- `truncated`：输出超过正文预算。
- `incomplete`：包含未完整解释的终端控制，或执行被中断。
- `mixed`：已知后台输出可能混入；此时不自动附正文。
- `terminal_source`：来源是合并的终端流，不是 stdout/stderr。

命令和 cwd 的证据展示各自最多 1,024 字节，并标记裁剪；真实执行命令和 shell 状态不因此截断。

## 4. 会话 PTY 架构

```text
原控制终端
    │ 原始输入 / 原始输出 / resize / signal
    ▼
外层 relay（不创建 shell 或模型）
    │ PTY master                    私有 Unix socket
    ▼                              │ B/E/F + command_id
内层 host：唯一 brush + REPL + harness + engine
    │ PTY slave（控制终端）
    ▼
用户前台命令
```

### 4.1 启动

- 在 Tokio runtime、模型线程和 shell rc 启动前，外层进程创建 PTY 与 socket，并一次性 re-exec 内层 host。
- 内层 host 验证 socket 对端是直接父进程；环境变量里的 fd 数字本身不是能力。
- 内层取得 PTY 控制终端，随后才加载 rc 和创建唯一的 brush `Shell`。用户与 agent 因此继续共享 cwd、非导出变量、函数、alias 和 venv。
- 外层确认转发所需描述符可等待后才把原终端切到 raw mode，并放行内层 host。
- Linux 通过 poll 等待；macOS 复用 `filedescriptor` 的 select 后端，避免 Darwin 对 `/dev/tty` 返回 `POLLNVAL`。

### 4.2 控制协议与边界

控制 socket 使用固定帧，当前事件为：

- `B(command_id)`：开始记录该命令。
- `E(command_id)`：结束并返回快照。
- `F(0)`：审批前清空外层和内层 typeahead。

事件不使用 OSC、prompt 文本或程序可打印字符串，因此命令输出不能伪造开始、完成或授权。

内层在 B/E 前 flush stdio 并对控制终端 `tcdrain`；外层收到事件后继续排空当时可读的 PTY 字节，暂停下一提示符，再确认边界。排空等待最多 2 秒、边界期间最多处理 256 KiB；无法形成可靠边界时关闭控制通道并把采集标为不可用，而不是假报完整。

### 4.3 转发、信号与退出

- 外层只用固定大小块和每方向一个待写块转发，不积累无界发送队列。
- 原终端 SIGWINCH 更新 PTY 大小；相关信号转发到 PTY 当前前台进程组。
- Ctrl-C、Ctrl-Z/fg 和交互读取继续由控制终端与 brush 作业控制处理。
- 审批前必须同时清除 relay 待转发输入、原终端输入和内层 slave 输入；任一环节失败时拒绝审批。
- relay 正常退出或失败时恢复原终端设置，只回收本会话创建的 host。
- `exec` 可以关闭私有控制 socket；PTY 仍继续转发，但之后不再声称有可用采集。

### 4.4 启动降级

PTY 创建、控制终端验证、对端验证或就绪等待失败时：

1. 在执行用户 rc 和命令之前显示明确警告。
2. 继续使用原 shell 路径，保证 shell 可用。
3. 不使用 `2>&1 | tee` 或 agent 管道路径冒充兼容采集。
4. 输出状态为不可用，而不是成功空输出。

运行中控制通道失败不会重启 shell，也不会重放 rc 或用户命令。

## 5. 文本处理与预算

用户看到的字节不经过清理；以下处理只作用于证据副本：

1. 增量 UTF-8 解码，跨块字符保持完整，非法字节显示为 `�`。
2. 流式 VTE 解析移除 ANSI、OSC 和其他控制载荷，不保存其完整 payload。
3. `\r` 进度行只保留最后一次覆盖的文本。
4. 其他隐藏字符转义，避免模型或日志中不可见的控制效果。
5. 备用屏幕模式标记 `FullScreen`；无法完全解释的光标/设备控制标记 `incomplete`。
6. 清理后的尾部最多 **4,096 字节**，不拆 UTF-8 字符。内部流式缓冲同样受限。

`printf x > file` 没有终端输出时得到有效的空 `Captured`，不会读取 `file`。stdout 和 stderr 都写到 PTY 时自然合并，顺序以终端实际观察为准。

## 6. 任务消息与信任边界

证据使用单独的动态段：

```text
[user_output {"command_id":17,"command":"cargo build","execution_cwd":"/work/app",
              "exit":101,"source":"terminal","state":"captured",
              "observed_bytes":1234,"retained_bytes":1234,
              "truncated":false,"incomplete":false,"mixed":false}]
error[E0308]: ...
[/user_output]
```

- JSON 元数据防止命令换行与正文混淆字段。
- 执行 cwd 与任务请求时的当前 cwd 分开。
- 空输出明确写成成功空采集；不可用状态明确要求模型不得编造错误文本。
- 已知混流只附状态，不附正文。
- `Message::User` 经模板的 untrusted segment 编码；正文中的 `<|im_end|>`、`<tool_response>` 或 `<function>` 不产生消息、工具或权限边界。
- 输出只提供证据，不改变工具集、风险等级、审批策略或是否允许执行。

## 7. 隐私与持久化

- 采集槽只在内存保留最近一条输出，不写入 shell history、agent `outputs` 或新建的 scrollback 日志。
- 发送给模型后，证据成为当前内存对话的一部分，直到对话被清空、空闲重置或进程退出。
- 本地模型沿用 `NoRedact`，因此可能包含命令输出中的秘密；`capture_output` 不是脱敏功能。
- 显式启用 `NOSH_EVAL_TRACE` 时，trace 按既有契约记录模型实际收到的完整 user message，包括输出证据。
- 不新增网络出口。未来远程 agent 必须在独立设计中定义脱敏、保留期限和传输策略。

## 8. 已知限制

- 首版只保证无并发输出的前台命令；不能识别所有写入 PTY 的进程。
- 后台作业存在时保守标记 `mixed`，可能牺牲可用性以避免错误归属。
- 交互程序开启的输入回显可能出现在终端流中，不能与程序输出可靠分离。
- 全屏程序标记不可用，不尝试保存或重建屏幕。
- 尚未实现按需读取成功命令输出的 `get_last_output` 工具，见 §11。
- 失败证据第一次进入模型后会留在该诊断对话中，直到对话重置。
- 原生 Windows 不支持此 PTY 后端。

## 9. 验收与评测

无模型回归至少覆盖：

- 500 个连续命令边界及伪控制标记。
- 一次性报错夹具：首次模型请求包含原诊断，执行计数仍为 1。
- 100 MiB 连续输出：终端完整收到，证据正文仍不超过 4,096 字节并保留末尾哨兵。
- UTF-8 跨块、非法字节、ANSI/OSC/DCS、回车进度行和隐藏字符。
- 成功空输出、重定向、全屏、混流、取消和旧失败清理。
- `cd`、非导出变量、函数、alias、venv 的共享状态。
- Ctrl-C、Ctrl-Z/fg、交互输入、resize、审批 typeahead 和终端恢复。
- `off`、`-c`、脚本、非交互、`-a/-s` 及 PTY 启动降级。
- special token 文本保持数据身份。
- Linux x86_64、Linux ARM64 和 macOS CI。

真实模型评测将**采集与关联**、**诊断有据性**、**明确的 diagnostic_id 引用**分开报告。有限规则只能发现已覆盖的矛盾，不能证明所有自然语言解释都正确；历史数据集和报告不因新口径改写。

## 11. 后续 TODO：`get_last_output`

- [ ] 新增无参数模型工具 `get_last_output`，按需返回最近一条已结束用户命令的采集快照。

目标契约：

- 只加入普通 agent 的完整工具集，不加入 Ctrl+G / `nosh -s` 建议模式。
- 不执行或重跑命令，不读取重定向文件，不扩大为历史输出查询。
- 返回命令 ID、命令、执行 cwd、退出码、耗时、来源、状态、观察/保留字节数以及截断、不完整、混流标记。
- 只有 `Captured && !mixed` 时返回已有的有界正文；`off`、不可用、全屏、已知混流和成功空输出按各自状态返回，不能编造正文。
- 工具结果继续是不可信数据；special token、权限和审批边界与当前 `[user_output]` 相同。
- 同一对话对同一命令 ID 只返回一次完整正文；重复调用返回短状态引用，避免重复占用上下文。对话重置后可重新读取。
- 当前失败诊断继续直接附带匹配 ID 的证据，不要求模型先调用工具；该工具主要服务于用户明确要求解释最近一次**成功或非失败**命令输出的场景。
- 本地只读风险分类、远程 agent 的脱敏和保留策略在实现前单独确认，不能因工具只读就忽略输出中可能包含的秘密。

验收至少覆盖：无输出、`off`、PTY 不可用、截断、全屏、混流、命令切换、对话内去重、对话重置、special token，以及调用工具时程序执行计数不增加。
