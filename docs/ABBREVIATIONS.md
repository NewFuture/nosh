# 可见命令缩写

缩写只编辑 nosh 正常交互终端中的草稿，不是 Bash alias。展开后的完整命令留在输入行，可继续修改；脚本、`nosh -c`、agent 直接执行及外部 Bash 集成都不经过这条路径。

## 输入与撤销

尚未展开的可用缩写在输入反馈中直接显示名称与准确展开值，例如 `gst → git status`，不附加 `Input:` 前缀；窄终端按显示宽度裁剪，不改变实际输入。内建深浅主题用蓝色强调缩写、绿色显示已识别的普通命令；alias/函数使用加粗强调色。`NO_COLOR` 下保留展开文字，不依赖颜色区分。

| 操作 | 行为 |
|---|---|
| 手写 `gst` 后输入空格 | 精确命中当前可用规则时变为 `git status `，继续加参数。 |
| 手写 `gst` 后直接 Enter | 先在输入行展开，再正常验证、提交；不完整语法继续编辑，不额外要求一次 Enter。 |
| Tab | 使用原有补全；展示缩写名、准确展开和来源。完整结果唯一时回填，多项时显示菜单；缩写不抢占真实命令候选。 |
| 菜单中的 Enter | 只接受候选，不执行，也不对插入值二次展开。 |
| Ctrl+Space | 插入空格并保留本条原文，不自动展开。 |
| Ctrl+Z、Ctrl+_，或 Vi 的撤销动作 | 一次撤销恢复展开前文本与可继续编辑的光标；本条随后保持原文，不被空格或 Enter 立刻展开回来。 |
| 重做 | 重放原文本变更，不重新检查规则或运行命令。 |

保护持续到本条结束或清空。粘贴、内部粘回、历史导航/搜索/灰字接受、AI 建议和交接回填都保护**整份草稿**，包括后来手写的部分。这些内容仍可用 Tab 明确选择展开；一次选择不会解除其余内容的保护。

Ctrl+Space 或撤销展开明确保留原文后，不因未展开的词触发本地纠错、Tab 的 AI 无结果兜底或失败后的自动 AI。F2、`# 任务`、`#fix` 等主动入口不受此保护限制；真实 alias/function 仍按 Shell 原本语义执行。

Ctrl+Space 的命名动作是 `literal_space`，默认用于 Emacs、Vi 插入编辑；可按[输入编辑配置](INPUT-EDITING.md)改键。菜单、搜索、选区与 Vi 待完成操作仍拥有自己的按键。传统终端的 NUL/Ctrl+@ 使用同一个归一化入口；输入法或终端截获的按键不能由 nosh 保证收到。

终端支持 bracketed paste 时，粘贴来源来自实际粘贴事件，不按输入速度猜测。不支持该协议、把粘贴伪装成逐键输入的终端无法可靠区分来源；可先用 Ctrl+Space 明确保留原文。基本终端不提供自动展开和原生撤销，管理入口仍可用。

## 内置规则与适用性

首批只维护以下十条。未确认适用的条目仍可查看，但不会作为可用缩写或可接受的补全候选。

| 名称 | 展开 | 支持条件 |
|---|---|---|
| `ll` | `ls -lh` | 已确认 GNU `ls`，或经参数探测确认的 uutils / macOS 系统 BSD `ls`。 |
| `la` | `ls -lAh` | 同上，包含隐藏项但不包含 `.` / `..`，使用长列表及人类可读尺寸。 |
| `..` | `cd ..` | `cd` 是启用、未被 alias/function 替代的 Shell 内建。 |
| `...` | `cd ../..` | 同上。 |
| `gst` | `git status` | 已确认外部 Git 2+。 |
| `gd` | `git diff` | 同上；不另提供 `gdf`。 |
| `gds` | `git diff --staged` | 同上。 |
| `gb` | `git branch` | 同上。 |
| `glo` | `git log --oneline --decorate` | 同上。 |
| `glog` | `git log --oneline --decorate --graph` | 同上。 |

判断针对当前实际解析到的命令，不只看操作系统或文件名。uutils 和 macOS BSD 的检查使用 `ls -ldAh .`，只查询当前目录自身、验证展开需要的参数；失败不启用。`ls` 指向其它工具的 alias/function 不会被当成标准 `ls`；其他未确认的实现（包括当前未适配的 BusyBox 配置）不自动套用参数。可以自行定义所需用法。

**内置规则不抢占同名命令、函数或 alias。** 自定义规则默认也让位，只有明确 `--override` 才优先；覆盖内置同样需要显式标记。保留字、带空白/引号/转义的名称以及当前前缀管理命名空间不能用作缩写名。

检查只确认规则适用性，不证明某次执行成功、安全或已获权限。例如 `git status` 在非仓库目录失败仍是正常 Shell 行为。不会自动安装或下载 Git、ls 或其它工具，也不会把现有 alias 全部导入。

## 管理

提示符内使用 `#abbr`，前缀随 `ai_prefix` 变化；也可在任意终端使用 `nosh abbr`。两者使用同一组操作和用户配置：

```sh
# 在 nosh 提示符内
#abbr
#abbr set gmain 'git switch main'
#abbr set gst 'git status --short' --override
#abbr disable ll
#abbr enable ll
#abbr disable --builtins
#abbr enable --builtins
#abbr disable --all
#abbr enable --all
#abbr remove gmain

# 外部终端，或 AI 已关闭
nosh abbr list
nosh abbr set gmain 'git switch main'
```

`list` 显示名称、准确展开、来源、可用情况与原因，包含被关闭/覆盖的内置规则。`remove` 只删除用户定义；删除覆盖项时明确提示内置条目重新按其开关和适用性判断。`disable --all` 不删除定义，也不清空单条开关。

添加或修改用户规则只检查该名称的冲突和该展开文本，不探测无关的内置目标；例如 Git 的能力检查超时不妨碍添加一个 `echo` 缩写。PATH 中已确认不可执行的普通文件不占用命令名，无法检查的目录仍明确报告不确定性。

独立 `nosh abbr` 看不到父 Shell 未导出的 alias/function，输出明确标识检查上下文，不重新加载一个 rc 冒充原会话。`#abbr` 查看当前会话的真实状态。原有前缀命名空间在 AI 全局关闭时不启用，但 `nosh abbr`、配置读取及缩写本身不依赖模型。

自定义展开是非空、固定、单行 Shell 文本；允许普通引号、参数、管道和连接命令。管理和展开时不执行变量、命令替换或其它 Shell 内容；真正提交后才按 Shell 语义求值。不支持正则规则、动态生成函数、光标占位符或多行模板，不递归展开生成的词。

## 配置与刷新

沿用平台的用户配置路径，见[系统配置](DESIGN.md#11-配置)。

```toml
[shell.abbreviations]
enabled = true
builtins = true
disabled = ["ll"]

[shell.abbreviations.rules]
gmain = { expansion = "git switch main" }
gst = { expansion = "git status --short", override = true }

[shell.keybindings]
literal_space = ["Ctrl+Space"]
```

命令写入仅更新相关字段，与主题共用配置锁和原子替换，保留无关内容、注释和文件权限。无效规则、只读/链接文件、并发修改等失败明确报错，不覆盖旧文件。

新配置在下一条新输入生效，不在正在编辑的草稿上换目标。当前草稿只允许撤销已失效规则的可用性，不把旧候选换成新定义；候选接受前再次检查版本及实际插入值。尚未完成能力确认的规则不会在已开始输入的草稿中悄悄变得可用。

清空草稿会重新采用已经确认的规则目录，包括检查结果在此前编辑期间已被读取的情况；没有必要再提交一次空行。达到已展开范围记录上限也不会解除用户明确选择的“保留原文”。

命令冲突和可执行性在新提示符后台重新检查；解析到的程序身份、cwd 和 PATH 相同且文件身份未变时，版本/能力结果最多复用 5 秒。不监控所有外部文件变化，也不把缓存快照当作执行成功保证。无实际变化的检查结果不打断正在进行的补全；规则撤回时关闭失效候选并明确保留当前原文。

正常执行后，Shell 将已经确认的同一路径写入命令 hash 缓存，不会因此撤掉缩写。显式改绑目标路径、同名命令新增或其它解析环境变化仍使相应快照失效。后台检查尚未确认适用性时，规则不拥有该名称，真实 PATH 命令仍正常输入和提交，不必先执行一次来预热 hash。已经确认、但不适用于本份冻结草稿的规则不会偷偷换目标；可清空后重试，或用 Ctrl+Space 明确保留原文。

启动时配置读取/结构错误会停用相应缩写配置并提示；刷新失败保留上一有效配置并说明未刷新，不静默恢复默认规则。配置、Shell 状态、环境变化与能力结果采用版本化快照，过期结果不能覆盖新状态。

## 语法与资源边界

自动展开是命令位置的精确匹配，和候选搜索是两回事。支持可靠的行首、常见管道/命令连接、静态赋值和重定向后的命令词，保留两侧文本和 UTF-8 字节光标；普通参数、引号/转义词、注释、here-doc 正文、前缀管理命令和自然语言请求不自动替换。

参数或重定向文件名中出现 `for`、`case` 等字样不视为控制结构，也不阻止后面真正命令位置的缩写，例如 `echo for; gst`。

位置判定复用 brush 的线性、引号感知分词辅助，不在按键回调运行完整 parser。对命令替换、复杂复合结构及可能改变解析环境的前序内容保守停止，不猜测新的命令位置；自动展开不是完整 Bash 重写器。

| 项目 | 内部上限 |
|---|---|
| 用户规则与关闭名称合计 | 256 项 |
| 单个名称 / 展开 | 128 字节 / 8 KiB |
| 规则内容 / 输入及展开结果 | 各 256 KiB |
| 位置分析 | 4,096 个词法项 |
| 已展开范围及一次替换 | 256 项 |
| 能力探测 | 1 个 worker、1 个进行中、1 个最新待处理快照 |
| 探测请求 / 单个程序输出 | 首次冷启动 3,000 ms，后续 1,500 ms / 4 KiB |
| 外部命令查找 | 至多 128 个 PATH 目录 |
| 配置读写 | 1 MiB |

这些是拒绝/降级边界，不是每台设备上的输入延迟承诺。超限保留原文并说明原因，不静默截断。

提交时若展开事务超限或无效，该次 Enter 留在编辑器中，不部分改写后继续执行。可修改输入、取消，或明确使用原样输入方式。普通有效规则仍遵循一次 Enter 展开并提交的契约。

能力检查使用固定版本/选项探测、空 stdin、受限输出与受控进程归属，不在编辑、重绘或候选导航时启动程序。首次请求给进程初始化和工具冷启动有界余量，显式管理查询整体最多等待 4,500 ms，编辑器始终不等待探测。探测程序本身不是沙箱；未知/超时不算成功。取消或超时后的未回收任务继续占槽；连续失败暂停检查，成功响应重置连续失败计数，不无限启动替代进程。U6 的 worker 与 U1/U3 的开关独立，不要求打开高亮或补全才能使用空格展开。

展开读取编辑器侧的不可变快照，不竞争探测结果的发布锁；后台更新结果时也不会把普通的空格、Enter 或 `exit` 拒绝为“快照忙”。编辑错误独立保存，通知合并或发布锁忙不会丢失反馈。

实现入口为 `nosh-shell::abbreviations`；U1 消费同一规则及本条意图，U3 使用同一候选定义并在接受前校验。Reedline 只负责可撤销文本事务、来源状态与编辑事件，Shell 规则留在 nosh；补丁维护见[源码维护](REEDLINE-MAINTENANCE.md)。本功能不改变历史存储方案，也不能撤回已经执行的命令。
