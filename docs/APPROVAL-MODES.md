# 三档审批模式：询问 / 自动 / YOLO

> **当前实现。** AI 任务缺省使用 `auto`。本文对应 #32 的权限实现，取代 #31 发布时的“目标设计、默认仍为 confirm”说明。
>
> **实施时确认的调整**：常见 build / test / check 在自动模式下直接执行，即使项目代码的实际影响无法完全分析；这是一项明确的便利取舍，不是可恢复性证明。用户 deny、未被用户白名单覆盖的内置禁止，以及已经识别的显式高风险仍优先。
>
> **产品取舍：便利优先，同时防御破坏性操作，而非追求绝对安全。** 普通 `mv` / `cp` 在 Auto 下默认执行；仅因理论竞争窗口就要求原子不覆盖、备份或额外审批的收紧已撤销。明确危险目标、破坏性命令和用户禁止仍按矩阵处理。

## 1. 范围与入口

只有 `confirm` / `auto` / `yolo` 三档，显示为 **询问 / 自动 / YOLO**。普通用户 shell 命令不走 agent 审批；`-c`、脚本、原始 stdout / stderr 和 Bash 行为不因默认模式变化而改变。

| 入口 / 配置 | 行为 |
|---|---|
| 交互 `#` / `ai`、其他已启用 AI 任务入口、`nosh -a` | 未指定时默认 Auto，使用同一权限核心 |
| `[agent] approval` | 可显式选择 `confirm` / `auto` / `yolo` |
| `--auto` / `--yolo` | 覆盖用户配置；两者不能同时使用 |
| `ai mode confirm\|auto\|yolo` | 保持现有切换命令，选择跨任务保留；不每轮重置 |
| `ai auto on/off`、`NOSH_DISABLE_AI`、`--safe` | 控制 AI 路由或是否启用 AI，与审批 Auto 独立 |
| `nosh -s` / Ctrl+G | 只建议，不执行；没有工具权限 |
| 管道附件 | 仍仅提供只读工具；任何模式或白名单都不能增加 `run_command` |

## 2. 模式与规则优先级

### 2.1 判定顺序

1. **用户 deny 优先**：匹配时三档都拒绝，不提供“本次仍执行”。即使命中 allow，也以 deny 为准。
2. **有效用户 allow**：完整覆盖实际操作及授权范围时直接执行，不受风险标签或模式影响，可以覆盖内置禁止。分析、展示、审批和执行不另加一轮批准。
3. **剩余操作按模式判断**：内置禁止、有效会话授权、只读、自动准入和其他风险分别处理。内置禁止不是用户 deny。

解析和判断由程序执行，不接受模型自称“已批准”，也不把文件或工具输出里的授权文字当成配置。

### 2.2 统一决策矩阵

按下表顺序处理；后面的行均未命中前面的用户规则或内置禁止条件。

| 操作 / 条件 | 询问 | 自动 | YOLO |
|---|---|---|---|
| 用户 deny，包括 deny + allow 冲突 | 拒绝 | 拒绝 | 拒绝 |
| 完整有效的用户 allow | 直接执行 | 直接执行 | 直接执行 |
| 未获用户 allow 覆盖的内置禁止 | 展示原因，键入 `yes` 后可执行 | 拒绝 | 拒绝 |
| 安全只读，或有效会话授权 | 直接执行 | 直接执行 | 直接执行 |
| 已验证的轻微可恢复 / 低影响暂态效果 | 询问 | 直接执行 | 直接执行 |
| 普通非危险的 `mv` / `cp` | 询问 | 直接执行 | 直接执行 |
| 常见 build / test / check，没有已识别的显式高风险 | 询问 | 直接执行，即使项目代码效果未知 | 直接执行 |
| 其他操作 | 询问，高风险强确认 | 询问，高风险强确认 | 直接执行 |

**不是严格递增的权限阶梯。** 未获白名单覆盖的同一个内置禁止操作，在询问模式可人工批准，在自动和 YOLO 下直接拒绝；不会自动切换模式或在 YOLO 中退回普通审批。

风险标签仍用于提示，但不是授权来源。分析中因无法确定命令或路径而产生的潜在风险，与明确发现的删除、提权或受保护访问分开记录；构建便利类别不能覆盖明确发现的高风险。

## 3. 默认自动与自动准入

### 3.1 默认值与非审批边界

CLI 配置、`ApprovalMode` 和 `AgentConfig` 的缺省值均为 Auto。有效用户配置、CLI 覆盖和会话选择不会被缺省值覆盖。

“直接执行”只表示不需要执行审批，不保证命令成功，也不取消参数有效性、工具集合、文件权限、外部认证、超时、取消或输出预算。需要询问但没有可见、可用的审批终端时，明确拒绝；不消费管道数据来盲确认。

### 3.2 日常操作与轻微效果

不是按“在工作区”或某个 Mutating 标签直接放行。当前覆盖包括：

| 类别 | 自动准入依据 | 反例 / 限制 |
|---|---|---|
| 目录 / 空文件创建 | 明确目标及已有父目录，`mkdir` / `touch` 本身不截断现有文件内容 | 额外重定向、特殊文件、未知范围不自动准入 |
| 普通文件移动 / 复制 | 识别为 `mv` / `cp` 且实际参数、目标没有命中危险规则时，默认执行；不要求内容预算、Git 恢复对象或原子执行机制 | 用户 deny、受保护读取、系统 / 受保护目标、移入 `/dev/null` 等破坏性效果仍处理；不把额外重定向或未知脚本当作普通移动复制 |
| 其他文件内容重定向 / 删除 | 仍按对应风险要求批准或有效授权 | 不因属于文件操作就继承 `mv` / `cp` 的便利准入 |
| 时间戳变更 | 能读取普通文件原有访问 / 修改时间，原状态记录在决策原因中 | 特殊文件或无法取得原状态不自动准入 |
| 目录 / 普通变量 | 作用明确，旧目录、值及相关导出状态可得 | 关键执行环境、未知变量属性、不可逆属性设置、任意 source 不因此放行 |
| Git | 真实 Git 状态和对象作为证据：暂存 / 取消暂存、创建本地分支、满足干净状态和有界差异要求的切换、常规新提交、受限的远端查询 / fetch | hooks、凭据助手（含 URL 范围配置）、askPass 等可执行配置需授权。fetch 仅接受标准远端跟踪 refspec，记录跟踪 refs 和 tags，拒绝配置的 prune / pruneTags / mirror 及额外 refspec；冲突、force / reset --hard、发布和任意远端写入不因此放行 |
| 运维只读 | 使用命令及子命令规则识别服务、容器、接口、路由、防火墙状态等查询 | 变更网络 / 防火墙配置、停服务、重启、刷写等不是只读 |
| 网络诊断 | 普通单目标 ping、有限 DNS 查询，结合实际执行期限和选项判断低影响 | flood、广播、高负载选项、区域传送、上传或任意远程执行不因此放行 |

当前内部边界包括：一次调用中依赖文件效果证据的路径累计最多 32 个，普通变量的新旧值各最多 1 MiB；Git index 恢复最多 32 项，分支切换最多 32 个变化路径且新旧内容总计最多 1 MiB。复合命令里的文件变更范围相互重叠时，不复用执行前证据。Git 证据子进程使用本会话的导出环境，不继承宿主进程中已被会话取消的环境变量；单次最多读取 64 KiB、等待 2 秒，失败或超限会说明原因并请求审批。普通 ping 使用不超过 60 秒的执行期限，并限制可识别的计数 / 时间选项。

有效用户白名单、有效会话授权、普通 `mv` / `cp` 和构建便利类别不受上述恢复证据预算约束。`mv` / `cp` 保留原生命令的参数和覆盖语义，不悄悄添加 no-clobber、不自动备份或回滚，也不承诺消除所有外部状态竞争。不能以“没有原子不覆盖机制”为由对普通移动复制额外询问。明确的危险操作仍须审批或拒绝；这不等于把任意未知程序升级成已知工具。

### 3.3 构建 / 测试便利类别

这是实施阶段确认的新要求，替代原设计中“未知 build/test 必须询问”的限制。

当前识别 Rust / Go 的构建、测试、检查，npm / pnpm / yarn 的常见 build / test / check / lint 入口，make / ninja 的默认构建或明确构建测试目标、`cmake --build`、ctest、pytest / `python -m pytest`、tsc，以及部分明确的 Gradle / Maven 等构建测试形式。不是允许这些工具的所有子命令。

- 不要求先批准项目，也不要求先证明每个插件、测试、build script 都可恢复。项目代码可能联网、修改文件或产生其他未知效果。
- `cargo run/publish/install`、任意 `npm run <script>`、`make deploy/install`、一般未知脚本、`eslint --fix` 等不因“开发工具”名称自动进入该类别。
- `cargo fmt` 仅在显式 `--check` 时进入检查类别，普通格式化和 `cargo clippy --fix` 仍需授权；已识别的源码改写不被当作只读检查。
- `tsc --clean`、`meson compile --clean` 属于清理输出，采用普通确认而非构建直通；`tsc --init` 是配置初始化，继续便利放行，不因为创建配置而提升为高风险。显式 `--tsBuildInfoFile` 与其他输出参数一样参与目标路径检查。
- 构建操作不能替同一行的额外命令、输入替换或外层重定向提供授权。已识别的用户 deny、内置禁止、显式高风险和受保护读取仍先处理。
- 多任务工具逐项检查目标：`mvn test deploy`、`gradle build publish`、`cmake --build build --target install` 不因首个任务是构建 / 测试而直接放行。网络诊断、Git 等准入也不覆盖额外的文件重定向；组合命令包含构建便利类别时始终保留未知副作用说明。
- 若用户配置了资源级 deny，而不透明程序的效果无法排除该禁止范围，会保守拒绝并解释原因。便利类别不能绕过用户规则。
- `tsc`、ESLint、Meson、Bazel、sbt 等配置驱动构建器同样标记未建模的项目效果，不会因缺少显式输出参数而漏掉资源级 deny；没有匹配的禁止规则时仍保留构建便利准入，不扫描整个项目来证明安全。
- 便利类别要求能识别实际程序和参数，避免用未知参数隐藏 `--fix` 等模式；这不要求证明项目内部代码的所有效果。任意 `/tmp/cargo` 等路径程序不因 basename 相同而获信任；标准系统工具和已支持的项目 `./gradlew` 入口保留对应行为。
- 不因构建理论上可能修改目录状态，就强制拆分 `cargo test; cat result.log` 等所有组合命令；对分析时已识别的受保护读取、危险写入、删除及用户 deny 仍照常处理。构建内部代码和执行期间的状态变化没有沙箱级隔离保证。

这类准入会明确显示“项目代码的效果不保证可恢复”，不标为“已经安全备份”。任意程序内部效果不可完全静态推导；这不是操作系统沙箱。

## 4. 用户规则与会话授权

### 4.1 可读的统一 TOML 规则

保留项目现有 TOML 格式，使用同构规则条目；公开命令字段是字符串，内部解析为 argv。没有混合裸字符串 / 对象 / 参数数组的重载，也没有命令 `**` 或正则 DSL。

```toml
[agent]
approval = "auto"

[[safety.deny]]
command_prefix = "docker system prune"
reason = "Keep lab volumes"

[[safety.allow]]
command_prefix = "git fetch"
cwd = "."
reason = "Allow project fetches"

[[safety.allow]]
command_exact = "git status --short"

[[safety.allow]]
tool = "read_file"
path = "*.md"
cwd = "."
```

也可使用标准 TOML inline table：`allow = [{ command_prefix = "git fetch", cwd = "." }]`。旧 `allow = ["git *"]` 字符串数组不再接受；项目尚未发布，不提供旧格式兼容层。

| 字段 | 含义 |
|---|---|
| `command_prefix` | 按参数边界匹配前缀。`git fetch` 匹配 `git fetch --all`，不匹配 `git fetcher` 或 `git -C other fetch` |
| `command_exact` | 完整命令及参数匹配；与 prefix 互斥。保留引号 / 转义产生的参数边界，不对原始命令做整行 glob |
| `tool` | 命令选择器缺省为 `run_command`；其他工具显式填写 `read_file` / `list_dir` |
| `cwd` | 调用目录所属的目录树；相对路径以固定 workspace 根为基准，省略时不限制目录；不等于限制全部文件效果 |
| `path` | 只读工具目标 glob；相对模式以 workspace 为根，支持绝对 / `~/` 模式。`*` 不跨目录，`**` 是路径递归匹配，不是命令参数语法 |
| `read_paths` / `write_paths` | 限定命令的实际读 / 写 / 删除范围；外层重定向必须获得相应授权 |
| `variables` | 限定变量效果；命令前面的额外环境赋值不能借命令前缀被隐式批准 |
| `hosts` | 限定已解析的网络目标；无法解析的复杂 URL、配置或间接目标不能冒充匹配 |
| `max_depth` | `list_dir` allow 的深度上限，1–3；deny 不会因请求更深而失效，因为更深的遍历仍包含被禁止的浅层范围 |
| `name` / `reason` | 可读名称及理由；未命名时显示配置条目位置 |
| `allow_opaque` | 显式接受匹配规则下的不完整 shell 分析；不解除用户 deny、命令匹配或资源范围检查。完整匹配的独立脚本调用不会仅因内部代码未知而二次审批 |

配置里的命令选择器只解析字面量 shell 词，不执行变量展开、命令替换或文件名展开。路径 glob 不接受 `..` 穿越，应改用明确的绝对 / home 模式；命令字面量及实际 shell 路径的语法不受此配置限制。

路径规范化保留原始范围类型：`.//**`、`././/**` 仍是工作区相对模式，不会变成绝对 `/**`；home 模式中的重复分隔符也不会改变 home 范围。

条目内部条件按 AND 组合，deny 总是先于 allow；不靠条目顺序或用户填写的优先级数字改变这一点。资源范围无法证明、变量 / 命令参数不确定时，不能把部分匹配解释成完整授权。

可读字符串、显式作用域和内部参数匹配参考了 [Claude Code](https://code.claude.com/docs/en/permissions)、[Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/cli-best-practices#configure-allowed-tools)、[Codex](https://developers.openai.com/codex/rules) 与 [Gemini CLI](https://geminicli.com/docs/reference/policy-engine/) 的常见做法；这些工具没有统一的权限配置语法，nosh 不声称格式兼容。

### 4.2 匹配实际调用

分析记录工具、参数边界、cwd、文件目标、变量效果及脚本调用关系，不用展示字符串做授权。

工作区、home 和受保护目录同时按配置路径与解析后的根路径比较，包含 macOS `/System/Volumes/Data` 等目录别名。相对路径规则和自动准入使用同一根范围；只归一化范围根，不把工作区子目录中指向外部的符号链接视为工作区授权。

裸命令名通过 shell 的有效 PATH/cwd 和命令 hash 信息定位实际程序；工作区内的同名替身按未知本地程序分析，而不是直接继承 `mv`、`cp`、`cargo` 等内置分类。用户安装在项目外的工具和已激活虚拟环境不要求额外的系统目录白名单；不是对整个 PATH 做可信认证。Git 探查使用同一个已解析程序，防止探查系统 Git 却执行另一程序。

复合命令的局部 allow 不会扩大为其他命令获批；已允许的脚本调用可覆盖其自身实际 payload，但不能覆盖兄弟命令，也不能把别名名称当成真实程序。带脚本 / 包装器选择器的 deny 检查该调用及所有后代的聚合效果，不会漏掉“父操作匹配命令、子操作匹配禁止路径”的组合，也不会把相邻命令误当后代。范围约束、不确定作用域和内置默认风险分别判断。

构建便利类别只由展开后的真实操作获得，alias/function 仅因命名为 `cargo` 不会授权任意子操作；包装正常构建命令仍保持自动执行。exact deny 保留未引用纯展开参数可能消失的信息，不会因多出分析占位参数而漏掉实际精确匹配；带固定文本或普通引号保留的参数不当作可消失，allow 也不会因此放宽。

路径选项统一提取实际值，例如 `-t/etc`、`--target-directory=/etc`、`--prefix=/etc` 和 `--file=/etc/pom.xml` 与分开书写的参数使用相同路径规则；分开传入的字面量值不会被再次当作选项前缀剥除。

GNU 工具的路径长选项缩写（如 `sort --out`）也保守记录为潜在路径效果，包括可能有歧义的前缀；不会因缺少完整选项名称而当作只读。绝对路径模式同样解析固定根，`/alias/**` 和其真实目录保持同一授权范围，子链接逃出该根则不能继承 allow。

`touch -r` / `--reference` 的时间戳来源也记录为读取效果，不能被普通目标文件的写入范围掩盖。

`sort -o` 同时记录输入读取和输出写入，选项消耗的值不会误报为输入文件；输出重定向不能掩盖受保护文件读取或用户的 `read_paths` deny。

已支持的短选项组合也保留取值边界，例如 `sort -roFILE`、`cp -vtDIR`、`curl -sSoFILE` 和 `wget -qOFILE` / `-qPDIR`；其他取值选项的参数不会被误当作该路径选项。导出的 `SSH_ASKPASS` 对联网 Git 操作按认证助手处理，不因此对普通本地 Git 操作增加审批。

`sudo -n` 改写及防卡住环境变量在匹配时按实际执行语义处理。仅归一化紧随 `sudo` 的非交互选项，不从其他参数或选项值中删除 `-n`。编辑、符号链接目标或相关会话 / 脚本状态变化后重新分析；仍完整匹配用户白名单时不再审批。隐藏字符可见地转义，不用它们伪造显示授权。

`run_command`、`read_file`、`list_dir` 都检查用户规则。读取路径采用准备后的同一结果；read_file 实际会为计数读取返回区间之外的内容，不能把授权理解为“只读取显示的行”；list_dir 的遍历深度和子范围也属于授权对象。

### 4.3 会话授权与配置错误

审批卡片的 `a` 仅复用**相同操作与有效范围**，绑定实际参数、目标、能力、环境上下文和脚本版本，不按前缀合并 / 扩大能力。无法提供明确范围、不透明程序、受保护读取和高风险不提供这种授权。一次批准内置禁止不会产生会话或持久白名单。

有效会话授权不重复询问，但不覆盖用户 deny 或内置禁止。权限来源、拒绝理由和实际失败均可见。

不存在配置文件时使用缺省值；配置存在却不可读、TOML 无效、审批值或安全规则非法时，阻止 AI 工具执行并报告原因，不退回空 deny + Auto。普通用户 shell / 脚本仍可用，纯建议入口不取得工具能力。

## 5. UI 标识与实时状态

当前提示符 / badge 显示 `审批: 询问`、`审批: 自动` 或 `审批: YOLO`；默认是 **`审批: 自动`**。英文环境使用对应的 `Approval` 标识。

“等待你批准 / 正在执行 / 待你处理”与模式分别显示，不能视为第四档，也不与 Emacs / Vi 输入模式混淆。沿用 `ai mode` 切换，不新增快捷键、菜单或完整 UX 方案。

动作、结果、拒绝和错误不会因自动执行而隐藏。受限终端提供纯文本等价显示；非交互、重定向和 JSON 不插入常驻装饰，stdout / stderr 及原始用户命令字节契约不变。

## 6. 验收覆盖

实现使用策略 / 作用域单测、真实临时夹具、MockChatEngine、CLI 和 PTY 覆盖。禁止项的允许分支在最终执行边界使用测试替身，不在宿主机执行破坏性命令。

- deny + allow、完整 allow + 内置禁止、内置禁止三档差异、非禁止高风险的审批与执行次数。
- 脚本 payload 与兄弟命令、别名、包装器、替换、重定向、参数边界及编辑后的重新匹配。
- 普通移动复制零审批且实际执行、危险目标与用户 deny 仍拦截、真实 Git 恢复对象 / hooks、网络诊断与反例、构建未知效果便利类别及显式高风险反例。
- 会话范围不扩张；HOME 与工作区变化不取消原用户 home 的禁止；执行环境与授权分析一致。
- 默认 / 显式覆盖 / 会话选择保持、只读工具范围、无可见审批终端、模式 / 状态及 JSON / 管道输出。

历史 MVP 的用例数、确认比例和真实模型评测不是新模式的实测数据；不改写历史报告。

## 7. 取消、恢复及其他边界

三个模式都不代填密码，不绕过 root / 外部认证，不自动重试整条交接命令。终端交接明确提示复合命令前面的副作用可能已经发生。

用户已有的 SSH 配置属于运行环境的信任边界。nosh 不为普通 Git SSH 远端解析或执行 SSH 配置来验证 `ProxyCommand` / `Match exec`，也不因使用 SSH 就一律要求审批；这些配置可以运行用户配置的辅助程序，不能将当前 Git 检查理解成对整个 SSH 执行链的沙箱保证。用户 deny、已识别的危险操作和外部认证契约仍然有效。

拒绝 / 取消待批调用不执行该调用；正在运行的命令被中断与整个任务取消是不同状态。取消不撤销已经发生的效果。当前会话输出记录保留相关决策与可得的变更前状态，不提供通用备份、`ai undo`、整任务事务或自动环境回滚。

不包含新写入工具、设备管理集成、环境自动安装、项目 / 管理员策略、远程审批、系统沙箱或输入编辑 / 高亮 / 补全改造。#19 的写入 / 撤销与 #23 的编辑模式、后续切换 UX 分别设计。
