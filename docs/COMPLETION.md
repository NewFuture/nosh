# 命令与参数补全

单独键入 `#`（或配置的 `ai_prefix`）立即弹出本地命令菜单，不需要先按 Tab 或回车；`#theme ` 和 `#mode ` 在输入到参数位置时自动展示候选，标记当前项并附简短说明。Tab 仍可主动打开候选菜单，输入可过滤候选，方向键/Tab 选择，菜单内 Enter 采用候选，再次提交才执行命令。自动展示即使只有一项也不回填、不切换设置。菜单打开后，输入变化并闲置 300 ms 会刷新脚本候选；导航和重绘复用已有结果。

根菜单首项为 `# <task>`：选择只补一个空格，继续输入任务并提交后才进入 Agent，不把占位文字写入草稿。开始输入子命令名后，该项不参与筛选；自定义前缀遵循相同规则。帮助也将这一入口放在首行。

显式请求得到完整、未截断的唯一候选时可以直接回填；自动弹出的前缀菜单也可由 Tab 接管为显式补全。自动刷新只更新菜单；部分结果由用户明确选择。同一输入的后台刷新按候选身份保留选择；旧选中项消失时要求重新导航，避免误选。主动编辑输入或改变补全位置后，按当前结果重新选中第一项，不需要额外按方向键或 Tab，也不会自动回填或执行。取消保留草稿并使旧查询失效。引用、空格、Unicode 和行中替换使用完整插入值，显示截断仅作用于菜单。

普通输入的显式 Tab 请求支持异步兜底：本地查询最终完整无匹配，且原草稿、光标、选区、编辑模式和版本仍有效时，接力一次 CommandAssist，不需要再按 Tab 或 F2。查询中、部分结果和失败不视为无匹配；继续编辑、导航、取消或待处理输入会撤销旧请求的自动接力。管理命令、历史搜索和 Literal 原样输入不进入该路径。接受建议仍只回填，前台生成可用 Ctrl+C 取消。

无候选时不绘制空列表或 `NO RECORDS FOUND`，仅保留当前状态和适用退出操作；查询、失败和失效选择的必要原因仍明确显示。空菜单的提交保护不变，不因省略空态正文而执行草稿。

## 支持范围

| 来源 | 覆盖 |
|---|---|
| nosh 前缀命令 | `#` 子命令、`mode`／`think`／`assist` 固定参数及 `theme` 内建名称；使用配置的 `ai_prefix` |
| 命令名 | 当前启用的 builtin、alias、function、PATH 和 hash 中的有效外部命令 |
| 路径 | 当前相关目录的文件／目录、`cd`、重定向及已知路径参数 |
| Git 2.23+ | 子命令名称；`switch` 的选项、冲突样式、分支／起点及已支持的全局路径参数 |
| GNU Make | 常用选项、路径参数、字面目标、静态 `.PHONY` 和 include |
| npm／Yarn | `npm run`／`run-script`、`yarn run`／快捷调用中的项目脚本名和说明 |
| 已加载补全定义 | `complete`、`compgen`／`compopt`、函数／命令、自动加载及定义允许的回退 |
| 缩写 | 所有者启用的适用规则；明确选择后回填准确展开并通知所有者 |

原生命令／路径使用轻量子序列模糊匹配，完整、前缀、其它模糊依次优先，同分稳定。Smart case 折叠 ASCII 大小写，含大写的查询严格匹配；路径的 `nocaseglob` 设置优先。参数提供器使用各自的前缀规则。

nosh 前缀命令使用共享命令目录在编辑器内直接完成，不调用脚本、PATH 或隔离 worker，不请求模型；菜单替换范围保留原始前缀，不插入转义的 `\#`。未知名称和没有固定候选的参数返回完整空结果，Tab 无结果也不进入 AI。AI 禁用时不启用此命名空间。

前缀自动菜单只在 Emacs／Vi 插入编辑中、光标位于前缀或未完成子命令名末尾时打开或恢复，不自动回填唯一候选。继续键入、退格和删除均更新候选；从完整命令名或无匹配输入删回可补全前缀时也会恢复菜单。名称已完整、没有匹配项、输入或粘贴空格／任务正文时收起，因此完整键入 `#help`、`#fix` 或 `# 任务` 后仍可直接回车提交。Esc 取消后，重绘、光标移动、撤销和历史搜索不会重新弹出，继续编辑可恢复补全。普通 Shell 的 Tab 菜单不受此规则影响。

自动参数菜单跟随 `ai_prefix` 和 `completion` 开关。Esc 关闭后保留草稿，在离开该参数位置或进入新提示符前不自动重开，仍可主动按 Tab。只在正常文本输入时自动展示，不抢占历史搜索、历史导航、选区或 Vi 普通/待完成操作；无参数直接提交仍是查询当前设置。当前项来自提示符边界快照，不在按键期间读取配置或运行 Starship。

普通 Shell 补全中，已加载定义优先于内置提供器，其顺序、`nosort/noquote/nospace` 和回退规则保持有效。查询失败、无匹配和部分结果分别报告。当前参数无需补全时保留 worker，执行故障才进入回收和暂停流程。`complete_or_ai` 仅在普通非管理输入完整无匹配时按现有输入编辑规则进入 AI 建议。

命令名验证使用请求内的有界时间预算；预算耗尽后停止新的外部文件验证，仍按原排序保留无需文件查询的 builtin、alias、function 和已验证的外部候选，并遵守候选上限，缩写在最终集合中只加入一次。慢 PATH 返回部分候选及明确原因，不继续验证到外层 worker 超时。原生查询发生超时或故障时，同一请求已经发布的有效候选保留为部分结果；不沿用旧请求或已过期缓存，不把未完成查询视为完整无匹配。脚本失败及没有有效候选的故障仍明确报告不可用。

Make 静态读取规则、转义、续行和 include，CLI 路径参数使用分离值或长选项 `=值` 形式，按顺序读取已导出的 `GNUMAKEFLAGS`／`MAKEFLAGS` 中的 `-I`／`--include-dir` 路径；动态目标、条件、模式规则和未支持的 include 选项形式标为不完整。npm／Yarn 查找最近的 `package.json`（npm 显式 `--prefix` 限于指定目录），支持子命令前的 `--prefix`／`--cwd` 及 `=值` 形式。Yarn 快捷调用排除已知内置命令同名脚本，显式 `yarn run` 可补这些名称。脚本参数、workspace 和插件命令由已加载定义提供。

## 配置

```toml
[shell]
completion = true
completion_scripts = true
```

`completion_scripts = false` 跳过已加载脚本提供器，使用内置／原生来源；动态路径仍在隔离 worker 中展开。它与 `input_assist` 独立。`completion = false`、AI 禁用或空前缀不自动弹出命令菜单。基本终端、非 TTY、脚本和 `-c` 使用原有降级路径；无菜单时提交单独前缀仍显示帮助。

## 执行与资源

原生和脚本查询共用一个 worker。每个请求在后台调度阶段解析一次，上下文与执行类型随请求传递，等待和生成阶段复用结果。原生查询使用轻量快照；脚本按需恢复当前 shell 状态，自动加载及脚本改动保留在 worker 内。

**已加载脚本可以执行程序、访问文件或联网，`--offline` 不约束这些脚本。** 内置 Git／Make 会运行解析到的程序做查询（含 `--version`）；Makefile 和项目脚本名仅静态读取。取消和超时回收可确认归属的任务；未回收任务继续占槽。持续故障暂停自动刷新，显式请求可在回收后重试。

| 项目 | 上限 |
|---|---|
| worker／队列 | 1 个 worker，1 个执行中、1 个最新待处理；InputAssist 另有 2 个 worker |
| 请求期限 | 普通原生 500 ms；PATH 索引／脚本 1,500 ms |
| 集合／菜单 | 16,384 项、4 MiB；菜单 256 项；超限标记部分结果 |
| 缓存 | 集合 6 MiB，显示及派生副本 2 MiB |
| 输入／词 | 256 KiB／8 KiB |
| 快照／IPC | 原生 256 KiB、脚本 4 MiB、帧 8 MiB |
| Make 读取 | 合计 2 MiB、32 个文件、8 层 include |
| package.json 读取 | 2 MiB、最多 32 层祖先目录 |

PATH 名称缓存约 5 秒，其它本地集合约 1 秒，在实际请求时检查有效期。缓存按 cwd、参数和会话复用完整集合，追加字符可找到上一屏以外的候选。同一 key 只保留最新完整集合，请求中发现过期或替换条目时释放其槽位与已计额度，不保留旧结果兜底；淘汰使用插入时记录的大小，不反复遍历候选重新计量。

## 扩展与嵌入

实现位于 `crates/nosh-shell/src/completion`：`context`／`snapshot` 提供上下文，`native`／`providers` 生成候选，`service`／`worker` 管理执行，`editor` 接入 Reedline。

菜单颜色从当前[主题快照](THEMES.md)读取，选中项、匹配部分和说明使用各自语义样式。目录采用下划线修饰，不把生成时的固定绿色缓存到后续主题。换色不重新请求候选，也不改变排序、当前选择、接受或关闭的键义。

新增命令在 `providers/mod.rs` 添加分派及候选函数，复用匹配、路径回填、集合限额和 `Cache::load`。嵌入宿主通过 `completion::Config.worker` 提供 `WorkerCommand`，内部入口调用 `input_assist::run_worker_from_env()`。

缩写所有者提供 `input_assist::Abbreviations` 的版本、适用名称和定义；`selection_observer` 直接接收 `&AbbreviationSelection`，包含 `name` 和 `revision`。源码准备与补丁维护见[源码维护](REEDLINE-MAINTENANCE.md)。

内置与自定义缩写由 `abbreviations::Session` 统一拥有，使用其当前草稿快照。选择前校验版本、适用性和准确插入值，拒绝过期候选而不修改草稿；接受后通知仍只发送一次。显式选择可以展开受保护的粘贴/历史/AI 草稿，不解除整份草稿保护。规则管理、默认键位及平台支持见[可见缩写](ABBREVIATIONS.md)。
