# 命令与参数补全

nosh 的补全在候选生成层区分原生命令、路径、可信内置定义和已加载脚本。普通补全不调用模型，不执行输入草稿，不运行任意 `--help` 来生成说明。

## 默认交互

普通打字不自动打开菜单。沿用输入编辑的 `complete`／`complete_or_ai` 动作；默认 Tab 打开补全或操作当前菜单，菜单 Enter 只采用、不提交。最终完整无匹配时的显式 AI 兜底仍属于 U2，不是候选生成的一部分。

打开菜单后，内容或参数上下文改变且闲置 300 ms，允许刷新动态脚本；仅移动选择、重绘或调整窗口不会重复调用提供器。原生集合在缓存有效且完整时直接重筛，不只在上一屏中搜索。取消、提交、离开辅助交互会使旧结果失效。

只有显式补全请求仍有效、没有后续输入／导航，而且结果完整、未截断、最终只有一项时才允许直接回填。自动刷新、部分结果、失效选择和失败不自动改写。手动选择当前有效的部分结果允许回填，但不表示候选集合已完整。

菜单刷新按候选身份保留选择，不按下标偷换。插入值与显示独立：说明、控制字符可见化、匹配高亮及显示截断不改变完整插入文本。行中替换保留其它参数，文件名的空格、Tab、换行、Unicode 和引号按 shell 语义插入。

## 来源与实际覆盖

| 来源 | 覆盖 | 边界 |
|---|---|---|
| 原生命令 | 当前启用 builtin、alias、function、有效外部命令及 hash | PATH 名称索引只提供名称；匹配外部候选在 worker 中验证可执行性 |
| 原生路径 | 当前相关目录中的文件／目录、`cd`、重定向及已知路径参数 | 不递归扫描项目或全盘，不以目录前几项声称全量最优 |
| Git | 实际子命令名称；`switch` 选项、冲突样式枚举、分支／起点；已支持的全局路径参数 | 至少 Git 2.23；不是全部子命令的参数库。只读机读命令，不 fetch、switch 或执行 Git alias |
| GNU Make | 常用选项、文件／目录参数、确定字面目标和静态 include | 不运行 `make -qp`、配方、`$(shell ...)`、`eval` 或生成 include |
| programmable completion | 当前加载的 `complete` 定义、`compgen`／`compopt`、函数／命令、自动加载及声明的 fallback | 不默认加载整个第三方生态；无法保真隔离的依赖明确不可用，不猜测 CLI 参数 |
| 缩写规则接入 | 所有者确认启用且适用的名称、准确展开、来源及版本 | 不实现 U6 管理／自动展开；只有用户明确选择才回填，不隐式二次替换或提交 |

已加载的显式、basename、default／initial／empty-line 定义优先于内置 Git／Make。提供器无匹配、没有提供器、部分结果和失败是不同状态；只有没有适用定义或定义明确允许时才回退，慢专属提供器不会先混入无关文件。

脚本顺序和有效 `nosort/noquote/nospace` 不受全局模糊排序覆盖。原生命令／路径默认使用轻量子序列模糊：完整、前缀、其它模糊依次优先，同分稳定。Smart case 仅折叠 ASCII：全小写查询忽略 ASCII 大小写，含大写则严格；路径显式 `nocaseglob` 设置另优先启用不区分大小写。保留原名称，不做 Unicode 规范化。Git 分支、Make 目标等参数首版仍按各自的前缀规则，不将模糊算法推广到所有参数。

Make 的静态读取识别字面规则、目标列表、静态 `.PHONY`、续行、注释、转义、配方边界和有界 include。条件、变量生成的目标、模式／archive 规则、动态 include 和未知结构不冒充已解析目标；已确定目标可显示，结果注明不完整。Include 只追踪当前目录或明确 include-dir 中可确定文件，不运行 Make 以重建缺失文件。

## 会话与执行边界

原生查询使用最小不可变快照，不持用户 shell 锁。脚本使用同版本、保留变量及属性／数组、函数及来源、别名、选项、补全定义、builtin 启用状态和位置参数的 brush 执行快照；不另起空白 Bash，不共享用户历史、jobs、终端和任意文件描述符。

脚本改动和自动加载只留在补全 worker，不写回用户 shell。临时 `COMP_*`、`COMPREPLY`、trap／作用域及有效选项按事务处理；异常、取消、过期请求不继续复用半恢复的执行实例。依赖自定义 builtin／描述符或交互 jobs 的提供器明确受限。

**隔离不是零执行或安全沙箱。** 用户加载的函数、`-C` 命令、word-list 展开等可以运行程序、访问文件或联网；菜单内闲置刷新可能再次调用。`--offline` 不限制这些程序自身联网。内置 Git 查询本地状态、Make 不执行文件；不能把所有已加载提供器都称为离线／无副作用。

只管理本功能拥有的进程。取消／超时会停止 worker 和受控子进程；无法立即回收的内核任务仍占额度，不能无限启动替代任务。主动脱离进程组／清除归属标记的脚本不承诺可完整回收；检测到不受控依赖会暂停，无法证明归属时不冒险杀其它进程。

## 资源预算与缓存

| 项目 | 上限 |
|---|---|
| worker／队列 | 原生 1、脚本 1；各 1 执行中和 1 最新待处理；未回收任务继续占位 |
| 请求期限 | 普通原生 500 ms；PATH 索引与脚本 1,500 ms |
| 原始集合 | 16,384 项、4 MiB；截断附带原因 |
| 菜单结果 | 256 项；不据截断的一项判断唯一 |
| 内存缓存 | 8 MiB，并限制条目数；按真实 cwd／参数／会话／来源依赖复用 |
| 输入／word | 256 KiB／8 KiB；超限不截断用户草稿 |
| 快照／IPC | 原生快照 256 KiB、脚本快照 4 MiB、帧 8 MiB |
| Make 读取 | 合计 2 MiB、32 个文件、8 层 include |

完整目录／refs／Make 集合采用短有效期；PATH 名称集合约 5 秒，其它本地动态集合约 1 秒，仅后续请求检查，不周期性全盘刷新。不同脚本上下文不跨整条输入误用缓存；相同当前请求去重，导航不重新执行。

这些是资源边界，不是所有设备／网络挂载的响应保证。Worker 复用 InputAssist 的 CPU、栈、地址空间或备用分配预算；同时启用 InputAssist 时另有其两个 worker，合计至多四个。超时不是“已经回收”，内存分配预算也不是全进程 RSS 保证。

首次故障后，仅在实际回收且获得新快照时允许一次自动恢复；持续失败暂停自动刷新。显式补全可安全重试，未回收槽位不能被重试绕过。失败、不可用和部分状态保留可信原因，不当作最终无匹配请求模型。

## 配置与嵌入宿主

```toml
[shell]
completion = true
completion_scripts = true
```

默认启用且不要求额外开启模糊匹配。`completion_scripts = false` 禁用 programmable provider，不偷偷用文件覆盖被禁用的专属定义；原生补全和输入分析开关彼此独立。基本终端、非 TTY、脚本和 `-c` 沿用原降级路径，不创建不可展示的后台菜单。

嵌入 REPL 的宿主为 `completion::Config.worker` 提供 `WorkerCommand`，并在自己的独立内部入口调用 `input_assist::run_worker_from_env()`。CLI 已在配置／rc／模型初始化之前分流该入口。没有入口时明确显示不可用，不恢复同步 shell 锁调用。

U6 所有者提供 `input_assist::Abbreviations` 的 `revision`、`applicable` 和可信 `definitions`，关闭／不适用的规则不能留在 applicable 集合。U3 不管理规则或自动替换；完整联合场景由 #28 组织。

## 实现与维护入口

补全实现集中在 `crates/nosh-shell/src/completion`，按职责定位即可，不需要注册通用提供器框架：

| 文件 | 职责 |
|---|---|
| `context.rs`、`snapshot.rs` | 解析当前参数，捕获当前 shell 状态 |
| `native.rs`、`matching.rs`、`cache.rs` | 命令／路径集合、匹配和有界缓存 |
| `providers/` | Git 和静态 Make 定义；共用程序解析、版本查询与错误处理 |
| `worker.rs` | 在原生或脚本 worker 中生成候选；脚本 shell 与运行时作为一个执行实例保存 |
| `service.rs` | 调度、期限、取消、回收和过期结果拒绝；复用 InputAssist 的进程与 IPC 机制 |
| `types.rs`、`editor.rs` | 集中定义结果状态与预算校验；将候选转换为 Reedline 显示／插入值和选择通知 |

编辑器直接使用当前候选及其显示身份，不另存缩写选择索引。新增候选来源时，先明确适用条件、匹配规则和失败／回退边界；不要为单一来源增加新的后台服务或缓存体系。

第三方补丁只适配 brush 执行状态和 Reedline 编辑器接口，不承载 nosh 的补全策略。构建来源记录（provenance）只供源码核对，不参与输入、匹配或候选排序；日常维护命令见[源码维护](REEDLINE-MAINTENANCE.md)。

## 固定环境基线记录

以下耗时记录于初版实现验证时，保留作对照，不代表每次重构都重新测得相同数值。

Ubuntu WSL、Rust 1.98.1、debug profile、无模型条件下，4,096 个真实目录条目的 fixture 首次查询约 39.1 ms，完整集合复用的 20 次查询 p50 约 5.62 ms、p95 约 5.79 ms；被首屏 256 项截断之外的目标在追加字符后排名第 1。

真实 PTY 的慢 builtin 循环／外部 sleep 场景中，编辑和取消显示约 10.3 ms，退出约 103–139 ms；300 ms 闲置刷新约 340 ms 到达。服务层取消约 44–49 µs，超时脚本约 1.525–1.531 s 被判定并进入受控停止／回收。记录的是该 fixture 的观测，不是对网络目录或其它设备的保证。

覆盖包括完整 workspace 回归、实际 Git refs／静态 Makefile、脚本状态与选项、队列／回收额度、清空环境的子进程归属、旧结果拒绝、引用／Unicode、U6 明确选择、Emacs／Vi、自定义菜单取消以及部分结果／自动刷新的回填边界。macOS 的资源／进程差异继续由 CI 覆盖；本次宿主实测不冒充 macOS 或 native Windows 应用验证。

源码适配采用固定官方 brush-core 0.5.0／brush-parser 0.4.0 和 Reedline 0.52.0，不更换引擎。
