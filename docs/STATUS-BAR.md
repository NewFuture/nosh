# Shell 提示符上方状态行设计

> **当前实现**：提示符上方使用紧凑分段：开发环境、上次命令结果与当前状态靠左，上下文、操作与模式文字靠右，空白不铺色；消费已有命令、InputAssist、CommandAssist 和 Agent 对话的真实状态。自动建议生成中、无建议和取消保持安静，仅展示有效候选及必要错误。已知限制与持续验收要求分别列出，不把实现完成等同于全宿主认证。
> **范围**：现有 Linux / macOS / WSL 交互 shell；原生 Windows 的独立编辑器验证不等于 nosh 的 Windows 移植。
> **关联**：[#36](https://github.com/NewFuture/nosh/issues/36)。输入辅助、会话 PTY、审批模式分别见 [INPUT-ASSIST](INPUT-ASSIST.md)、[OUTPUT-CAPTURE](OUTPUT-CAPTURE.md)、[APPROVAL-MODES](APPROVAL-MODES.md)。

制表符几何：输入中的字面 Tab 在绘制副本按当前物理列的八列制表位
展开为空格，ANSI/无颜色路径、行裁剪、resize 的已绘制行重流与鼠标字节映射
使用同一规则；原草稿、撤销、历史和提交参数保留字面 Tab。tmux 的未提交
草稿残留仍属于已知限制。

## 1. 功能信息划分

目标沿用 #36：在正常 shell 使用中，让用户知道**当前环境、正在发生什么、哪些操作有效**，不把所有信息挤在命令输入行，也不进入全屏聊天界面。状态层只读已有事实，不重做输入辅助、候选生成、审批或任务控制。

### 1.1 信息职责与字段

信息条按**环境 → 上次命令 → 当前状态 → 上下文 → 操作提示 → 模式**组织，不对应固定列槽位。环境内部可由 Starship 进一步分成目录、Git、运行时和虚拟环境；字段与开关见[主题说明](THEMES.md#按需出现的字段)。这里的优先级指哪些信息先保留、先压缩、先隐藏，不是开发分期。

| 分区 | 放置内容 | 边界与空值 |
|---|---|---|
| **环境区**：我在哪里 | 当前目录、Git 分支或短 HEAD；可选 Git 状态、语言版本和虚拟环境 | 默认复用提示符快照，附加开发字段交给显式启用的 Starship 模块；无数据不占位，自定义 PS1 时不额外注入该区 |
| **上次命令**：刚才运行的结果 | 非零退出码、至少 2 秒的耗时 | 只读实际 `UserCommand`，不把当前草稿、输入取消或 AI 输出当成用户命令；原生 Starship 片段接管结果时不重复 |
| **状态区**：现在是什么情况 | 当前输入反馈、有效 AI Next/Fix 候选、菜单/搜索及必要原因 | 一条主状态加相关细节，不堆全部后台消息；自动建议等待、无建议和取消不显示，不补“READY / 输入中 / 检查通过” |
| **上下文**：已有对话的容量 | 已用/最大 token 或紧凑百分比 | 与 `#ctx` 同源，85% 起警告色；无对话隐藏。只读提示符快照，不因显示加载模型或争用后台引擎 |
| **操作提示区**：当前可以怎么做 | 实际可用的“按键＋动作”，区分必要接受/退出/取消与通用帮助 | 只读提示，不是按钮、不注册新键位、不接管输入；不适用或无法确认的动作不显示 |
| **模式附注区**：采用什么模式 | 适用的真实审批模式；非默认编辑模式才附注 | 默认 Emacs 不常驻占位；审批模式有余量才显示，保留“审批”标签，不与 `#assist` 开关混淆；AI 全局关闭不伪造“自动”。等待审批仍属于真实决定状态 |

候选数量归状态区，编辑模式归模式附注区，不再另设“补充信息区”。“等待你批准”属于真实决定状态，不是模式附注；它由原审批界面显示，不反向恢复 shell 信息条。“自动 / YOLO”本身不代表正在审批或已经批准。

左侧色块宽度由实际内容决定，目录、Git、上次结果与当前状态连续相接；无状态时不画状态块。操作与模式组成右对齐的文字组，不铺背景。左右两组之间才留终端原背景；反馈变化可以重新分配水平空间，但不会增删上方行或移动输入行。

### 1.2 当前布局选择

采用随提示符流动的上方状态行，不维护固定屏底的另一套实现。

状态行是当前多行提示符的一部分，由同一个 Reedline renderer 绘制。它不固定在屏底或屏顶，也不把输入框固定在屏幕上。保留主屏、普通输出和宿主原生回滚，不引入备用屏前端。

| 项目 | 当前约定 |
|---|---|
| 位置与行数 | 默认提示符分为上方状态行和下方输入行；自定义 PS1 则在其整块内容之前附加状态。可用编辑尺寸下这行持续存在，即使当前状态为空；只有极窄/极矮、关闭或基础终端时退让 |
| 内容 | 左侧环境/状态分段，右侧操作/模式文字；状态同时消费 InputAssist 与现有 CommandAssist，不常驻无增量的“输入中 / READY” |
| 目录与分支 | 默认提示符的 cwd 和可取得的分支移入上方行，输入行只保留原提示符符号与草稿；自定义 PS1 不拆改、不额外注入目录/分支 |
| 长输入 | 状态随提示符正常滚出可见区；优先保证光标附近的输入可见，不复制一条悬浮状态行 |
| 命令提交 | 提示符与当时的状态快照自然进入正文历史，之后不再更新旧快照 |
| 非编辑阶段 | AI、审批和下载使用各自已有正文、卡片或进度区；不在旧提示符上维持一条全局实时栏 |
| 前台接管 | 停止提示符刷新，交出全部输入和完整终端尺寸；不擦除已经进入正文的提示符快照 |
| 配置 | `[shell] status_bar`；适用的交互终端默认开启，不提供位置选择或双实现 |

**可见屏正确重绘**、**正常提交快照留在历史**和**未提交草稿残留于宿主历史**是三件不同的事。前两项属于当前行为；第三项仍是已知限制，不能通过接受提交快照来豁免。

## 2. 信息布局

左侧按内容组织紧凑分段，右侧只显示当前可用操作与弱模式。示意中的方括号代表着色范围，不会实际打印：

```text
[目录][Git][运行时][环境][上次结果][当前状态]       ctx 用量  操作  模式
> 输入
```

普通草稿没有反馈时，目录/Git 之后不再延伸色块；空白输入显示历史入口，非空输入显示补全入口：

```text
[~/work/nosh][(main)]                Tab 补全  审批:自动
> git status
```

诊断出现时按需增加内容宽度的状态块；窄尺寸先保证原因与必要动作，再压缩环境或省略模式：

```text
[~/.../nosh][› 未找到 gti，建议 git]        → 采用 Ctrl+C 取消
> gti status
```

示例是布局说明，不是新布局的实测记录。文字和按键使用现有本地化、有效绑定和状态数据；`>` 代表原有提示符符号，不强制替换现有 `❯` 或 ASCII 退让。无 Git 或没有可靠分支数据时不画括号占位，不将 demo 的 `STATUS READY`、模型名、turn 计数变为产品常驻字段。

默认 cwd 按可用空间缩写，最多 64 列；Git 分支最多 28 列，空间不足时先省略分支。删除父级始终带 `.../`，优先保留末级或末两级；过长末级按完整字素裁剪，不伪装成家目录的直接子目录。完整 cwd 不变，`pwd` 仍可取得；自定义 PS1 不改。

普通空白草稿显示 `Ctrl+R 历史`，普通非空草稿显示 `Tab 补全`；主操作排在取消提示之前。可靠本地纠错优先显示建议与 `→ 采用`（ASCII 为 `Right 采用`），不叠加一般 Tab/历史键表。操作与模式只使用主题前景，不画背景或按键边框。必要取消及菜单/搜索采用、退出保留；建议入口使用实际 F2/改键，非空草稿不常驻通用生成图例。输入编辑与焦点键义以[输入编辑](INPUT-EDITING.md)为准，Ctrl+G 不是全局 AI 入口。

普通编辑中已有可采纳的历史灰字时，主操作改为 `→ 填入`（英文为 `→ accept`，ASCII 为 `Right accept`），不再叠加 `Tab 补全`；填入采纳已显示的建议，Tab 补全查询候选，两者不混用。改键后显示真实可用的采用键。灰字继续当前命令词时，状态栏暂不重复该词的“命令不存在”诊断；其他命令、路径、语法和资源错误仍保留。没有灰字、灰字不可采纳或进入菜单/搜索后恢复各自原提示。灰字不是输入，采用只回填，仍需明确提交。

各状态的字段组合见 §2.4，实际键义见 §2.5。示例中区域省略不等于功能停用，也不意味着原始状态或输入被删除。

接受有效候选或非空白草稿的 AI 建议只改变草稿，不顺带执行；空菜单、临时候选和空白草稿的键义不能类推，须单独核对。状态变化、重绘和缩放既不提交输入，也不产生授权。模式标识不表示某条命令已经批准，YOLO 也不代表 root 身份。

### 2.1 默认提示符、自定义提示符与关闭

| 场景 | 上方行 | 输入提示符 |
|---|---|---|
| 默认提示符，状态行可用 | 内容宽度的左侧色块与右侧文字；空白不着色，上方行数保持稳定 | 原 `❯` / `>` 与草稿，不重复目录/分支 |
| 自定义 PS1 | 环境区为空，保留适用的状态、操作提示及模式附注；不解析 PS1 猜测是否缺目录/分支 | 完整保留用户 PS1，包括多行和原有控制序列；不额外添加 `>` |
| 开关关闭、能力不足、整行无法布局或故障停用 | 不生成合并状态行；已有 InputAssist 反馈仍按原契约保留 | 默认提示符恢复原 cwd/分支与符号，自定义 PS1 不变 |

默认符号的退出码配色、无颜色行为和 PS2 续行语义保留。目录在状态行中因高优先级内容被压缩/隐藏，或整行随长输入自然离屏，**不**触发把目录搬回输入行；只有整行不再生成时才走关闭路径，避免反复挤占输入宽度。状态不在每个软换行或续行前重复。

布局、去重和退让使用同一份提示符快照，不因宽度变化再次展开 PS1、运行 `PROMPT_COMMAND` 或查询 Git；字段出现/消失不改变编辑缓冲区、逻辑光标或撤销记录。

### 2.2 与现有提示的合并

- 将已有上方 InputAssist 反馈纳入同一状态行，不再叠加“诊断一行 + 状态一行 + 固定底栏”。复用同一份事实和延迟，不新增分析或缩短命令未找到的既有约一秒等待。
- 诊断原文优先于通用快捷键提示；不能只保留 `!` 而删除其唯一文字解释。确需裁剪时仍保留原反馈数据，空间恢复后展开；不能把静态图例说成动态原因的完整替代。
- 按字段区分去重和主动省略：上方已显示审批模式时，右侧不重复；因低显示优先级主动隐藏模式时，也不转回右侧占位。其它未被承载的诊断或附注仍保留原提示路径，不能顺带隐藏整块 badge。状态行关闭、不可用或故障停用时，才按原契约恢复默认 badge 路径。
- `badge.note` 若有实际状态或错误，按其语义纳入状态区或保留原提示，不能因为和审批模式共用一个旧 badge 就一起降为弱信息。
- 自定义 PS1/PS2 及原有控制序列语义保持不变；只重组 nosh 自己生成的默认提示符。上方状态文字的清理不能作用于用户提示符或输入原文。
- 不新增详情快捷键、弹层、鼠标入口或状态专用命令。任务结果、错误、拒绝和人工交接仍完整留在对应正文。
- 上下文历史的范围、查询进度、错误、选中输入目录和有效按键复用状态栏；查询词留在原输入框，不在状态栏重复。按本帧实际显示的字段和动作去重，不仅检查开关：空间不足时，仅将未完整显示的说明或缺少的按键放回候选区；状态栏关闭或因长输入滚出可视区时恢复完整兜底。历史菜单不提供提交动作；等待查询不冒充无匹配，无有效选中项时不提示回填，确认无匹配时提示 Tab 退出搜索并保留输入，Enter 仍兼容但不重复提示。
- 历史候选的成功/失败/未知来自已保存的执行结果；折叠组结果混合时分别计数，同类结果只标一次状态。普通命令省略默认的类型、会话和本项目标签，仍明确标出其它来源及非普通命令类型。候选中的“失败(1)”不等于本次历史查询失败，不禁用回填，也不改变 Enter 的不执行边界。

### 2.3 数据来源与刷新边界

| 信息 | 来源与约束 |
|---|---|
| 默认目录 | 复用 shell 提示符准备阶段的 cwd 和现有 `~` 缩写；不从草稿中的 `cd` 或命令输出猜测 |
| 分支 / detached HEAD | 默认复用现有 `git_branch` 结果；显式启用 Starship 后由其模块提供 dirty/远端统计，不新增每键查询或第二套 Git 分析器 |
| 退出码 / 耗时 | 最近 `UserCommand` 的真实 exit / duration；不从草稿、stdout 或 Ctrl+C 输入取消推断，低于 2 秒的成功命令不常驻 |
| Agent 上下文 | `Agent::context_usage` 的现有对话统计；后台持有引擎期间使用移交时快照，不读取临时建议会话，不为状态行加载引擎 |
| 多行、诊断、查询状态 | 复用 InputAssist 的版本化事实和现有显示延迟，不另做一份分析 |
| 审批模式及附注 | 读取实际 AI 配置与 badge 状态；模式不是某条命令的授权，附注不因换位置丢失 |
| 菜单、历史、编辑模式 | 由当前编辑交互提供，`build_editor` 按配置装配 Emacs/Vi。数量、部分结果和查询状态只有真实可取得时才显示；Vi 插入/普通/选区状态不是审批模式 |
| 有效操作 | 结合当前输入所有者、草稿是否为空白、最近失败命令是否可用及实际绑定；界面提示不注册新快捷键、不消费输入 |
| AI、审批、下载阶段 | 原流程提供并在自己的界面展示；不从打印出的文字反推状态 |

返回新提示符时更新 cwd/分支快照；切换目录后不能沿用上一目录的分支。没有分支数据不代表 Git 干净或检查成功。编辑期间外部进程改变分支不承诺立即反映，下一提示符边界重新读取，不为此增加 watcher 或轮询。目录/分支文本和诊断一样需要清理控制字符，再计算显示宽度；完整路径与输入数据不因显示缩写被改写。

### 2.4 状态 case

以下是目标显示契约，不是运行通过记录。`常规环境` 指当前默认 cwd/可得分支，受自定义 PS1 和预算规则约束；`实际模式` 指真实编辑模式加可省略的审批模式，不表示两项必须显示。

| Case / 进入条件 | 环境区 | 状态区 | 操作提示区 | 模式附注区 |
|---|---|---|---|---|
| **C01 空白草稿，无最近失败命令或可用后台建议** | 主动缩写环境 | 无反馈则为空 | 实际历史搜索键；不堆 Tab/通用 F2 | 真实审批模式有余量才显示，不常驻 Emacs |
| **C02 普通非空白草稿** | 主动缩写环境 | 当前版本的适用反馈；没有则为空 | Tab 补全；可信纠错时让位于右方向键采用 | 同上 |
| **C03 空白草稿，有最近失败命令** | 当前目录，不冒充失败命令的执行目录 | 提示该失败命令的真实退出码；已有匹配的后台候选时按 C19 显示 | 有匹配候选时 F2/实际绑定采用，否则不显示快捷键修复；显式 `#fix` 仍可用 | 实际模式 |
| **C04 多行或待完成结构** | 可缩短 | 多行只描述草稿实际换行；仅已有事实确认为未完成时显示“待完成”及原因，完整多行不误报未完成 | Alt+Enter 换行、Ctrl+C 取消；不统一标“Enter 执行” | 实际模式 |
| **C05 语法/命令/必要路径诊断** | 为原因让出空间 | 复用主诊断和文字原因；命令未找到沿用约一秒延迟 | 取消及实际可用的辅助操作；诊断不是禁止提交的权限判断 | 审批模式先隐藏 |
| **C06 查询中或未知** | 常规环境 | 分别保留“查询中”或“未知”的真实含义，不合并为通过或错误 | 继续使用编辑操作，不要求等待才能编辑/取消 | 实际模式 |
| **C07 分析不可用、超预算或故障** | 常规环境 | 明确不可用原因，不能只显示正常颜色或空白成功状态 | 基本编辑/取消仍可用；不虚构“重试”键 | 实际模式 |
| **C08 已打开且有可采用候选的补全** | 可缩短 | 补全及真实候选数；完整候选仍在菜单 | Tab / Shift+Tab 导航、Enter 采用、Esc 关闭；仅在这些动作适用时显示 | 实际模式 |
| **C09 空菜单、临时候选或补全失败** | 可缩短 | 只按真实来源区分查询中、无候选、临时结果和失败；不能只靠数量 0 判失败/无匹配 | 不提示“Enter 采用”；Esc 关闭可用时保留，Enter 差异见 §5 | 审批模式先隐藏 |
| **C10 历史搜索，有匹配** | 可缩短 | 当前范围、实际查询状态和可容纳的输入来源；不重复输入框中的查询词或旧草稿诊断 | Ctrl+R 范围、Tab 回填、可导航时 ↑/↓ 选择、Esc / Ctrl+G 取消恢复；Enter 兼容但默认不单独提示，改键后采用有效绑定 | 实际模式 |
| **C11 历史查询中、无匹配或选中项失效** | 可缩短 | 明确区分查询进度、无匹配、需重新选择及错误；不显示假的成功状态 | 确认无匹配时 Tab 退出并保留输入，Enter 兼容；选中项失效但仍有候选时保留 ↑/↓ 重新选择提示，包括只剩一项；查询中或无可选项时只保留适用的范围/取消操作，不提示回填或提交 | 实际模式 |
| **C12 编辑取消/退出** | 新提示符重新取快照，或不再显示 | 旧输入反馈随当前编辑结束失效 | Ctrl+C 取消当前输入；Ctrl+D 的退出/删除含义依实际缓冲区区分 | 不恢复已结束的旧提示符 |
| **C19 后台 CommandAssist 排入/发布** | 当前目录 | 等待、无建议和取消不显示；空白草稿且 command ID 匹配时显示有效候选，真实失败明确报告并去重；输入使同版本的展示与取消句柄一起失效 | 有候选才显示实际 F2/改键采用，不为等待占用提示区 | 已有对话用量与实际模式，弱信息最后考虑 |

单个最终候选可能因现有 quick completion 直接填入草稿，不强制制造一帧“菜单已打开”；按真实活动交互重新取状态。查询结果到达、候选采用、搜索退出都不新增一次用户命令执行。

普通编辑的行内历史建议不是已采用的草稿，也不表示已进入历史搜索。历史搜索内选中项的灰色预览同样只属于显示，不是查询或命令输入；状态区不能把淡字建议当成当前输入进行诊断。实际采用后再按更新的草稿刷新，保留原有撤销语义。

这些情况是进入其它输入/显示所有者，不是在原提示符上继续更换信息：

| Case / 阶段 | 信息条 | 原界面必须保留什么 | 返回边界 |
|---|---|---|---|
| **C13 非空草稿的 AI 建议生成** | 暂停，旧行仅作已有快照 | 生成进度、原有取消方式、失败/无建议原因；不显示仍可用的 Tab/历史键 | 成功只回填；失败/取消按原流程保留草稿，重建当前编辑上下文 |
| **C14 AI 任务或显式 CommandAssist 请求** | 暂停 | Agent 保留阶段与停止动作；Generate/Fix/Next 沿用自己的查询、结果及取消路径，不将其说成 Agent 执行目标 | 原前台流程结束后才恢复提示符，不能被过期后台结果提前恢复 |
| **C15 审批、强确认、编辑及拒绝理由** | 暂停，不充当审批控件 | 当前决定、完整命令、真实执行目录、风险和有效选项在正文/卡片；模式弱化不删除决定信息 | 嵌套输入结束仍回原审批/任务流程，不直接恢复 shell |
| **C16 模型下载/加载** | 暂停 | 原进度、错误和原流程支持的取消；不再加信息条专用动画 | 完成后回调用者，不一律回 shell |
| **C17 用户命令、builtin、钩子、外部编辑器接管** | 不刷新，使用完整终端 | 原始输出和程序自己的输入界面；不依赖进入备用屏才让权 | 用户命令结束后按 B/E 边界建新提示符；编辑器内调用外部编辑器则恢复原编辑及返回的草稿，不制造新命令或重复运行提示符钩子 |
| **C18 任务结束、失败或人工交接** | 不用瞬时信息条代替结果 | 完整结果/错误/交接说明留在正文；不因刷新自动重试或执行交接命令 | 可继续编辑时更新环境及失败上下文；已完成的快照不再改写 |

配置和能力是叠加条件，不另复制一套状态机：

| 条件 | 对信息条的影响 |
|---|---|
| **M01 AI 全局禁用** | 去掉 AI 建议/诊断动作和审批模式；环境、编辑模式与独立启用的 InputAssist 不受影响 |
| **M02 `#assist off`** | 自动错误路由及自动建议暂停，不等于禁用 AI；F2 等显式入口仍按实际能力显示 |
| **M03 `input_assist = false`** | 不显示该分析器的诊断/查询状态，也不标“检查通过”；环境、菜单、历史和操作提示独立保留 |
| **M04 状态行关闭/不可用/故障停用** | 信息条不生成，走原提示符、badge 和 InputAssist 契约；非交互、基础终端及重定向不强开装饰 |
| **M05 自定义 PS1/PS2** | 环境区不自动注入；其它适用区在完整 PS1 之前，用户提示符及控制序列不被拆改 |
| **M06 `command_assist = false`** | 关闭自动 Next/Fix，不影响显式 Generate、Agent（包括 `#fix`）或 InputAssist；信息条不为补齐状态主动发起模型请求 |

### 2.5 操作提示必须匹配实际键义

本轮已核对现有 `repl.rs`、Reedline 事件处理及审批入口；下面不是新增键表，也不是运行时迁移已经通过的证明。

| 键 / 场景 | 文案与边界 |
|---|---|
| `#` 内置命令草稿 | 显示本地语法反馈及适用补全操作，不显示 F2 建议或后台候选采用 |
| F2（或改键），非空白普通草稿 | 生成建议，仅回填，不自动执行；辅助输入焦点中不可用 |
| 右方向键，当前可见且可信的本地纠错 | 仅普通编辑、光标在完整草稿末尾、无选区且原键位可用时采用；仅替换确认的原文字节跨度，保留参数/引用/Unicode/后续命令，可 Ctrl+Z 撤销。不会提交或授权 |
| 右方向键，其它情况 | 保留原移动、菜单导航和历史建议行为；纠错显示/可采用时历史灰字让位，避免一键两种可见建议。同批较早按键、输入/会话变化、菜单/搜索、缩放会使旧采用快照失效 |
| F2，空白草稿且有匹配的后台候选 | 优先采用现有候选；接收路径仍核对 command ID 并重新校验，不执行 |
| F2，空白草稿无候选 | 只提示，不新增模型请求，不按最近失败自动请求 Fix |
| Ctrl+G，普通 Emacs / 历史搜索 | 分别为保留的原生重做 / 取消恢复原草稿，不作为全局 AI 入口 |
| Enter，确实有可采用的补全结果 | 采用并返回编辑，不执行；无结果或临时候选不能沿用此标签 |
| Enter，历史搜索有效结果 | 与补全菜单一致，仅回填并返回编辑；再次 Enter 才按正常路由验证提交 |
| Enter，历史搜索已确认无匹配 | 退出搜索，保留当前输入和光标，不执行；查询中、失败或选中项失效不适用 |
| Enter，普通编辑 / 未完成输入 | 由现有 `LineValidator` 和提交路由决定，不根据诊断文字猜“执行”或绕过校验 |
| Esc / Ctrl+G / Ctrl+C，历史搜索 | Esc 与 Ctrl+G 恢复原草稿，Ctrl+C 取消整份输入；不能混为回填或普通关闭菜单 |
| Ctrl+D | 仅编辑器空缓冲时退出，非空时删除；这与 F2 使用的“去空白后为空”不是同一个条件 |
| 普通审批 | y/n；e/a 仅在 `can_edit` / `can_grant` 为真时显示；Esc/Ctrl+C 为拒绝/取消，不是批准 |
| 强确认、编辑命令、拒绝理由 | 分别使用原有 `yes` 文本确认、命令编辑和理由输入提示；不沿用外层 y/n 快捷键解释内层输入 |

提示读取真实绑定及动作适用性，不能建立会与事件处理漂移的第二套硬编码键表。尤其不能通过省略危险提示来掩盖 Enter 等按键的行为差异，相关路径必须通过独立回归。

## 3. 紧凑分段与单行预算

先去掉不适用、过期或重复的信息，再根据**实际文字宽度和终端列数**分配空间。状态/必要动作先取得可辨认的最小预算，然后考虑上次结果、环境、上下文与模式；余量优先展开操作和原因，再展开其它字段。未用于文字的预算可让回环境，不保留固定空槽。

状态行实际输出 `终端列数 - 1` 个显示列，但只对内容及其内边距着色，其余填充是**没有背景色的普通空格**。最后一个终端列保留为防自动回绕的安全余量；输入符号、草稿和命令输出不继承背景。相同内容在 80、120、219 列下不会因窗口变宽而拉长色块。`NO_COLOR` / `CLICOLOR=0` 保留文字预算与顺序，不输出样式。

真实 `Approval: Auto` 显示为 `Auto`（中文保留“自动”等值），空间不足时不显示模式，不从状态猜测模式。必要时使用标准 `^C` 记法表示实际 `Ctrl+C`，其它重绑键仍使用原键名。取消旧的 80 列 44/68 固定锚点约束；候选数量和状态可以改变上方内容的位置，但输入行、光标、草稿及菜单语义不变。低于 17 列或 3 行时统一让出整行。

| 当前交互 | 保留顺序：从高到低 | 优先退让 |
|---|---|---|
| 普通输入 | 当前主操作、目录、分支、模式 | 无状态块；长路径按可用空间缩写，模式可省略 |
| 出现诊断、未完成或不可用反馈 | 原因和必要动作、环境、附注/模式 | 优先缩短环境，不让弱模式挤掉取消/采用；原因不只剩 `!` |
| 补全 / 历史搜索 | 交互/原因及数量、退出/采用、环境、导航/模式 | 移除旧草稿反馈；窄尺寸省略次要导航，不把空/临时候选误标为可采用 |

**高优先级不等于必须完整展开。** 当前原因和必要动作先保留可辨认的短表达；模式是低优先级文字，不够时省略且不保留占位。

这里降级的是“询问/自动/YOLO”这类背景模式，**不是“等待你批准”这一当前状态，也不是确认、拒绝或退出操作**。真正需要用户决定时，原审批界面仍完整展示状态、命令、风险和选项；权限规则不变。

AI、审批和下载离开编辑器后由原界面显示，优先解释当前阶段/决定和真正可用的操作；完整命令、风险和审批选项不参与这条提示符状态行的裁剪。普通前台程序接管时不显示活动状态行。

同一信息组内也有不同权重：查询失败是当前状态，候选数量是补充信息；接受/退出是当前操作，普通输入时的 F2 通用提示优先级较低。不能只给“状态”或“操作”整组设置一个不变的优先级。

分配按同一帧快照完成。默认左侧的目录/Git、上次结果与当前状态连续相接，不插入露出终端底色的空隙；左右组之间按剩余宽度留白，右侧文字组内部仍用两列空格分隔。每个色块只带一列左右内边距，不绘制 `│` / `|` 分割线。字段中用户原有的 `│` / `|` 是文本，不会被删除。

默认 `nerd_font = "auto"` 在确认宿主内建字形支持时，为连续左侧分段增加一对外侧圆头，内部使用前后背景相接的 Powerline 楔形；未知宿主回退矩形。`true` 显式开启，`false` 关闭。端点计入预算，不延伸到右侧提示。没有合适颜色/字符能力时仍退让；显式开启时用同预算空格替代端点，有颜色的内部连接空格保留相邻段背景。原生 Starship 环境按自身格式显示，不重新包裹背景或添加一层端点；后接 nosh 状态时只衔接可识别的末端圆头，保留用户模板内部格式和留白。自动识别条件、生成、缓存和安全边界见[主题说明](THEMES.md#环境模块与-powerline)。

窄尺寸仍优先完整语义，路径按带标记的末级缩写，纠错可缩为
`gti→git` / ASCII `gti->git`。操作仍是完整 `→ accept` /
ASCII `Right use` 与实际 `Ctrl+C cancel` / `^C cancel`，
不截断采用键、不自动执行。英文极紧槽可使用 `Tab menu`、
`Enter use`、`Ctrl+R find`，仍指向原补全/采用/历史键义；
未找到命令的紧凑原因是 `No cmd`（中文“无此命令”），
菜单/搜索可使用 `Menu` / `History` / `No match`，不切成半个词。
先保证必要动作，再按余量展开文字，不为装饰牺牲真实键名。

菜单/搜索活跃时，状态区采用该交互的事实，不与旧草稿诊断拼接。普通编辑时沿用 InputAssist 现有主反馈选择：错误、不可用、待完成、查询中、未知等不能由显示层重新解释成安全等级；是否阻止提交仍由原校验和执行路径决定。

各组可处于不同密度，不改变终端字体或字号。终端变宽后按可用预算自动展开：

```text
颜色 + 符号 + 完整文字 + 样式
  → 颜色 + 符号 + 紧凑文字 + 样式
  → 紧凑文字 + 颜色 + 样式
  → 符号 + 颜色 + 样式
  → 隐藏次要文字，不保留色块占位
```

具体内容按 **完整 → 省略 → 一个完整字素＋省略标记** 收缩，不硬性为每项保留一个字符；关键语义仍须遵守下面的文字保留规则。

路径先沿用 `~` 缩写，再省略中间层级，尽量保留根标识及末级目录，例如 `~/…/nosh`，必要时为 `…/nosh`；根目录 `/` 和家目录 `~` 不缩为空。显示省略必须有标记，不能把缩写当成完整执行目录。裁剪只操作缓存文字，不为缩写查询文件系统。

静态模式/按键可在最窄时使用已有帮助可解释的符号；只有对应正文或反馈仍提供等价含义时，动态状态才可仅用图标。没有其它解释渠道的诊断不得只剩 `!`，必要的退出/停止动作也不能因路径过长被挤掉。若连有意义的短表达都放不下，则走局部退让而不是偷偷增加第二行，并如实记录该尺寸限制；不以“原文仍在内存”冒充用户已能读取完整含义。

- 复用 `style::width`、`clip_line`、`visible_text` 和本地化。按字素裁剪，正确计入组合字符、宽字符、分隔符和省略标记；不假定 emoji 固定一列。
- 使用可用列数减一的预算，避免状态行触发末列自动回绕。单项内容沿用 1,024 字节上限，超限按字素截断后附省略标记，最终文字仍须满足列宽预算；绝不截断编辑缓冲区或正文证据。
- 各分段采用克制的语义层次：环境有辨识度、普通状态安静、操作清晰、模式弱化但保持可读。明暗主题分别指定前景/背景，不使用 dim 或暗灰低对比文字冒充层级。状态与命令结果按各自语义着色，不把其它分段一并变色；没有 spinner，不把建议着成“已成功/已批准”的绿色。
- `›` / ASCII `>`、`!`、`?` 与真实文字仍辅助解释状态；色块不承担审批、风险或身份判定。内边距与内部连接都带所属段的背景，样式 reset 之间不插入无色分隔；末块在右侧留白及输入换行前恢复默认背景。
- 图标、端点和留白均计入列宽；每种外观的彩色与无色退化使用同一份文字预算。默认自动选择经确认支持的 Powerline 分隔符，未知宿主仅使用通用字符；其它 Nerd Font 图标需显式声明支持。不假定任意字体或 Emoji 固定一列，不新增动画或独立绘制循环。
- `NO_COLOR` / `CLICOLOR=0` 保留文字与符号并跳过仅颜色层级；Unicode 与颜色能力分别判断，不依赖 Nerd Font。
- 极窄时隐藏次要项，极矮或无法显示有意义内容时让出状态行；不增加第二行、不覆盖输入或候选。保留已有反馈路径，空间恢复后自动展开。
- 同宽状态切换不增删上方行；数字长度只影响内容预算。连续缩放由唯一编辑器重新布局和绘制，不由外部写入者移动光标；不得丢失草稿、撤销、选择或历史搜索状态。

### 3.1 分区色板、对比度和能力边界

终端不是 CSS：底色以等高、无描边的矩形单元绘制；自动或显式启用的 Powerline 端点是字符字形，可由字体或宿主内建渲染器绘制，不是 CSS 圆角。
内边距在彩色、无色、Unicode 和 ASCII 路径均存在；保留
`columns - 1` 输出预算和安全末列，不再保留旧固定槽起点。

内建 `soft-dark` / `soft-light` 在 [`theme.rs`](../crates/nosh-shell/src/theme.rs)
统一定义，覆盖提示符分段及输入、菜单、AI/审批和结果正文。`status/palette.rs`
保留成对颜色与语义区域接口。

RGB 和扩展色后备的普通/辅助文字对比度均按 sRGB 相对亮度检查，至少 4.5:1。
不会靠低对比的 dim 伪造信息层次，`!`、`?`、`›` / `>` 和真实原因仍保留。
色板、Starship 配置映射、非法值处理和预览入口见[主题说明](THEMES.md)。

已有 `Terminal.color` 仍控制 `NO_COLOR` / `CLICOLOR=0`。显示能力只在首次
读取环境时缓存：`COLORTERM=truecolor/24bit` 或直连 Windows Terminal
使用 24 位 SGR；只声明 `TERM=*256color` 时使用色板的扩展色索引（全部 >=16，
不使用通常被主题改写的 ANSI 0–15）；未声明扩展色支持或 linux/vt100/vt220
使用同预算的无色信息条，不猜测其默认前景/背景对比度。
tmux 不因为继承 `WT_SESSION` 就自动认定 RGB；仍需其真实广告能力。

这些对比值针对**请求的色板值**。宿主重新定义 256 色表、强制高对比映射、
透明度/背景混合、色彩滤镜或伪报色深时，不能承诺实际像素仍是请求的 RGB。
尤其 Win32 传统控制台属性只表示 16 色近似，不能用其“映射成黑色”认定
深色 RGB 块没画背景。实际效果需在稳定静态画面中检查前景/背景像素、
字体边界和整个行，至少在深、浅两种主题下独立观察；对比度回归不能
代替这一项。候选的宿主截图与实际颜色记录应单独保留，不操作用户现有窗口。

旧默认色板的历史截图不认证当前主题。[主题说明](THEMES.md#环境模块与-powerline)
保留代表性原生截图；PTY 观测、真实终端像素和物理显示器覆盖不能互相冒充。

### 3.2 内部主题注入与更新入口

`nosh_shell::status` 公开最小的类型安全配色接口，布局和业务事实仍由原
renderer 控制：

| 类型 / 调用 | 职责 |
|---|---|
| `ColorPair::new(fg_rgb, bg_rgb, fg_index, bg_index)` | 成对 RGB 与 256 色后备；索引必须在 16–255，错误显式返回 `InvalidColorIndex` |
| `Theme` / `StatusPalette` | 完整主题包含环境/状态分段、辅助文字和菜单选中项；`StatusPalette` 保留状态语义色，不包含布局、按键或风险策略 |
| `Theme::colors(Region, StatusTone)` | 按语义角色读取颜色，不靠文案匹配状态 |
| `ThemeHandle::new(theme)` / `snapshot()` / `replace(theme)` | 注入、读取及替换一个共享色板；相同值不重绘，更新后通知现有 editor 的 repaint 信号 |
| `ReplConfig.status_bar.theme` | 共享主题入口；每帧锁定完整快照，补全、搜索、高亮和历史提示消费同一帧，不因关条而关闭其它主题样式 |
| `ReplConfig.theme_loader` | 可选的提示符边界加载回调；CLI 用它只读取主题配置，不在每键或异步重绘时访问配置文件 |

```rust
use nosh_shell::{ReplConfig, status::Config, theme::{Builtin, ThemeHandle}};

let themes = ThemeHandle::default();
let repl = ReplConfig {
    status_bar: Config {
        theme: themes.clone(),
        ..Default::default()
    },
    ..Default::default()
};
// 把 repl 交给既有 nosh_shell::repl::run；宿主保留 themes 作为更新入口。
themes.replace(Builtin::Light.palette());
```

替换只更新色板并请求一次原生重绘，不重新构建 editor、不注入按键，不改草稿、
光标、选区、undo、菜单、历史搜索或审批模式。注册回调由当前 editor 持有，
退出后弱订阅不再重绘旧实例；回调在释放主题锁后执行。色板是固定大小的值，
锁内仅复制数据/处理订阅，用户代码不在锁内运行。

`NO_COLOR` / `CLICOLOR=0`、未声明扩展色、RGB/256 能力和 Unicode/ASCII 退让
仍先于色板；主题不能强行打开颜色或突破内容预算。内建色板有独立 golden。
用户覆盖经 `Theme::validate` /
`override_color` 检查；库宿主直接赋值后同样应验证对比度和实际宿主效果。

[视觉设计 #45](https://github.com/NewFuture/nosh/issues/45) 增加
`nosh theme list / preview / set / export` 与原生 Starship TOML 映射。选择自动保存，
保存失败不切换，无需重启；其他窗口的更新时机见[主题说明](THEMES.md#使用)。没有 watcher、插件或新的审批交互。

## 4. 刷新和终端所有权

### 编辑器拥有终端时

状态提供者只更新内存快照并调用公开的 `Reedline::repaint_signal()`；`Prompt::render_prompt_left()` 将默认环境与当次状态合成上方行，或将状态附加到完整自定义 PS1 之前。默认输入符号继续由原 Prompt indicator 提供。绘制回调只读已有快照，不执行 Git、模型请求、文件扫描或提示符脚本。

输入版本、上下文、候选、实际模式或尺寸变化才使布局失效。异步结果需与当前输入版本匹配；内容未变不因纯状态刷新重复写入。不增加状态专用轮询线程、时钟或 spinner，也不增加第二个终端读取者。已有诊断到期事件仍可无按键触发重绘。

每次绘制只读同一份可用快照，至少核对提示符/终端所有者、输入与会话版本及当前交互。候选/搜索结果还须对应当前查询；晚到结果不能覆盖后来的草稿或已经关闭的菜单。不要从本地化状态字符串反推这些事实。

| 状态转换 | 必须一起完成的更新 |
|---|---|
| 普通编辑 → 菜单/搜索 | 状态与操作提示同时切换，抑制旧草稿诊断；不重置输入、查询或当前选择 |
| 菜单采用/关闭、搜索采用/退出 → 编辑 | 以实际留下的草稿恢复反馈与操作提示，旧查询结果失效；反馈的恢复不能只依赖下一次命令提交 |
| 编辑 → 提交/取消/AI/外部编辑器 | 暂停或结束当前绘制所有权，暂停异步反馈；不能让一次晚到 repaint 重开旧提示符。外部编辑器返回原编辑，不按用户命令提交处理 |
| 子流程 → 调用者 | 先确认真正返回的输入所有者，再更新上下文；审批编辑、下载完成不等于 shell 已重新接管 |
| 新提示符 / cwd 或模式变化 | 更新真实快照并按字段去重，不沿用上一目录、失败命令或会话版本的数据 |

刷新只修改当前编辑器拥有的提示符区域，不重绘旧命令。长输入采用编辑器的光标可见视口，状态可自然离屏；返回 Home 或缩放时由同一 renderer 恢复，不另行查询光标并强行把状态拉回屏顶。

### 离开编辑器时

| 阶段 | 所有者与显示方式 |
|---|---|
| AI 建议、思考、工具输出 | 原 `AgentUi` / 建议流程拥有展示，阶段和动作放在其正文或已有进度位置；不回头刷新 shell 提示符 |
| 审批、强确认、编辑命令、拒绝理由 | 原审批输入器拥有输入；模式、命令、风险和完整选项保留在卡片中，不依赖状态行可见 |
| 模型下载或加载 | 保留原进度路径，不叠加状态 renderer |
| 用户命令、builtin、钩子、外部编辑器 | 原执行路径拥有完整终端；不能只在检测到备用屏后才停止状态刷新 |
| 已知后台 job 或未协作的 TTY 写入 | 沿用保守暂退/现有输出协调路径，明确记录限制；一把 UI 锁不能隔离外部进程 |

移除固定底栏不等于删除 AI 阶段和停止提示：命令的中断、整个任务的结束、菜单退出和审批拒绝必须仍在**当时接收输入的界面**准确表达。异步完成不能恢复过期提示符、覆盖回填草稿或改变审批 typeahead 隔离规则。

用户命令采集 `B` 之前完成当前提示符绘制和让权，`E` 排空并确认结束后才建立新提示符。目录与状态快照属于提示符，不属于该命令输出；不能靠事后删除“看起来像状态”的字节来净化证据。纯重绘不能被终端命令区域协议标成新命令，也不能触发环境钩子。会话 PTY 始终传播完整物理尺寸，`capture_output=off` 不为状态行新建 PTY。

返回 nosh 后重新取得尺寸、位置及当前上下文；已完成的提示符不再更新，取消不执行草稿。完整长命令在提交时必须保留，不能把编辑视口的裁剪结果当成最终命令记录。

### 能力不足与失败

继续检查真实输入/输出目标、ANSI 能力、控制终端和前台所有权。非交互、基础终端、重定向、脚本、`-c`、`-s`、一次性 `-a` 和 JSON 不混入装饰。

正常 resize、长输入离屏和空间不足不是故障；纯布局无法同时保留有意义的状态与必要操作时，该帧走原提示符/反馈路径。当前不再有独立的状态写入器，所以不保留旧 footer 的全局故障计数和装饰重试。反馈/补全状态读取失败会显示不可用原因；真正的终端写入或编辑器错误沿原 REPL 错误路径报告、退出并由编辑器恢复其模式，不通过重放输入伪造恢复成功。

新方案不设置专用滚动区域，不在退出时清空原生历史或全局 reset。既有编辑器和执行层仍须恢复其改变的输入、光标及终端模式；不可处理的强杀不承诺清理必然执行。

## 5. 技术方案与迁移边界

采用 **Reedline 0.52.0 + 局部渲染补丁 + 只读 Prompt 上下文接口**，本地修补源由官方上游 submodule 与同仓补丁生成到 `.nosh/reedline`，不再完整 vendor。多行 Prompt 和异步重绘是原有 API；新接口只提供真实编辑事实，不绘制、不扣高度。只升级到未修改的 0.52.0 不能得到本实现的显示与菜单提交边界。

| 层次 | 职责 |
|---|---|
| nosh 状态层 | `status.rs` 负责分段、预算、字符清理与样式；没有 `Display`、终端写入或滚动区域租约 |
| `ReplPrompt` / InputAssist / CommandAssist | 合成同帧快照，保留自定义提示符，处理版本、按字段去重和退让；worker 只发布结果与 repaint |
| Reedline renderer | 统一输入、菜单、光标、状态的几何；维护实际绘制行的重排、长输入视口和完整提交记录 |
| `TermUi` / `TerminalApproval` | 保留真实阶段与动作及原有交互，删除固定 footer 接线；不为提示符之外的阶段另建一套行编辑器 |
| shell / PTY / capture | 保留原执行、完整尺寸传播、采集边界和原始输出转发 |

渲染补丁跟踪上一帧的物理行及光标，处理 tmux 临时归档后返回可见区的自有前缀，按字素裁剪长输入并同步鼠标坐标。裁剪保留必要的颜色/超链接，不重放隐藏的光标控制或提示符标记；提交时保留完整输入和适用的右提示符。

补丁范围是 `painting/display.rs`、`painting/painter.rs`、模块接线及 `engine.rs` 的鼠标快照接线，不替换编辑、历史和补全实现。按固定基版、可审阅补丁及回归用例维护，优先争取上游吸收；尚无已发布的上游修复或已创建的远端 fork。

旧 `render_status_line` 接口已移除。`Prompt::update_context` 在真正绘制及 hint 生成前提供终端尺寸、完整草稿、字节光标、实际补全位置、选区、编辑模式及菜单/搜索状态；补全更新后再次核对最终事实。nosh 从编译后的实际模式/焦点键表导出提示，不维护另一套键表。编辑分派使用当时的引擎状态，不用此前绘制的快照猜焦点。

### 状态接线与边界

| 源码依据 | 设计及验证影响 |
|---|---|
| [`editing.rs`](../crates/nosh-shell/src/editing.rs)、[`repl.rs`](../crates/nosh-shell/src/repl.rs) | 模式/焦点有效键表、空白性和当前候选决定 F2/改键提示；保留 CommandAssist 接收与重新校验，缺少候选不假称快捷键修复 |
| [`completion/editor.rs`](../crates/nosh-shell/src/completion/editor.rs) | 提供当前候选、查询状态与真实错误；反馈由 renderer 显示，worker 资源和取消遵循[补全契约](COMPLETION.md)，不编造进度 |
| [`input_assist/editor.rs`](../crates/nosh-shell/src/input_assist/editor.rs) | 同一套分析发布带输入/会话版本的类型化反馈，保留完整显示原因及短摘要；与原关闭路径共存，搜索返回后高亮/反馈恢复，不新增分析器 |
| Reedline `with_menu_submit_protection(true)` | nosh 显式启用：空/临时候选菜单中的提交键仅关闭菜单，不静默执行草稿。未启用的上游默认以及显式 `MenuAccept` 不变，独立回归覆盖三种提交事件 |
| [`ui.rs`](../crates/nosh-core/src/ui.rs) | 结束任务、中断命令/再次结束任务的提示移入所属正文；没有任何后台 footer 写入或独立输入循环 |
| [`approval.rs`](../crates/nosh-core/src/approval.rs) | 请求携带权限判定时的真实 cwd，卡片显示执行目录；模式、完整命令、风险、有效选项和 typeahead 隔离保留，不改变批准策略 |

这些是窄范围的状态来源/提示接线要求，不是引入通用事件总线的理由。底层库支持的模式或异步能力，也不等于 nosh 已经启用并能对外提供相应状态。

工具链与依赖由 manifest、lockfile 和 source pin 固定。Cargo 选择本地修补源，不自动应用任意 `.patch` 文件，也不回退到原版依赖；准备、导出与升级见 [Reedline 维护说明](REEDLINE-MAINTENANCE.md)。

不引入 termwiz 自建编辑器、另一个 TUI renderer、私有光标回复路由或终端模拟器。保留成熟编辑能力，避免为改变状态位置重写整套前端。

## 6. 已知限制

- **宿主归档草稿**：tmux 的 `resize-160` 场景仍可能留下未提交草稿前缀；不能把关闭状态行视为通用修复。
- **保护原始内容**：不通过清空历史、截断输入、隐藏草稿或改成备用屏使指标通过；不主动拉回原生历史视口、取消选择或接管复制。
- **宿主覆盖**：布局和 PTY 用例不能证明所有 macOS、IDE、SSH、IME、物理鼠标或作业控制组合均可用，实际宿主仍需独立验证。

正常提交快照允许保留，不意味着接受未提交草稿残留。当前只维护本实现的行为与持续门槛，不维护旧 renderer 的对照报告或迁移流程。

## 7. 当前验收要求

### 7.1 验证矩阵

下表是**持续验收矩阵**，不是全部已通过清单。先使用纯布局夹具和编辑器事件断言，再用隔离配置、历史及 Mock AI/审批的真实 nosh，最后检查真实终端；开/关对照使用同一构建。不能仅凭画面看起来正确就认定输入、授权或采集正确。

| 验证 | 覆盖 case | 步骤与夹具 | 必须断言的结果 |
|---|---|---|---|
| **V01 分区、空值与语义** | C01-C11、M01-M05 | 构造有/无目录、分支、状态、动作、模式的组合及长字段；切换颜色/ASCII | 信息顺序固定但宽度按内容分配；空内容不生成色块，空白/右侧提示无背景；必要原因/操作不被弱信息挤掉，无信息不伪造成功 |
| **V02 预算、Unicode 与缩放** | C01-C11、M05 | 纯布局遍历列数 0–160，再测更宽长路径；组合字符、中文、Emoji、控制字符、候选数 9→10；宿主连续宽高变化 | 每行显示宽度不超过列数减一（零宽安全退让），不拆字素、不输出字段中的控制指令；终端字体差异单独记录，恢复宽度展开且不改草稿/选择 |
| **V03 反馈版本与延迟** | C02、C04-C07 | 快速纠正未知命令；等待真实约一秒到期事件；注入旧输入/旧会话结果、查询失败和资源上限 | 不提前报未找到、不接受过期反馈；错误/未知/查询中/不可用不混淆；光标移动/重绘不新增分析或 I/O |
| **V04 补全结果与采用** | C08-C09 | 0/1/多候选、临时/最终结果、故障；Tab/Shift+Tab/Enter/Esc；结果迟到时继续输入/退出菜单 | 提示与实际可采用性一致，单个最终候选可快速回填；无候选不冒充失败，失败不冒充无匹配；旧跨度不写入新草稿，菜单采用不意外变成提交 |
| **V05 历史与反馈恢复** | C02、C10-C12 | 行内建议的采用/撤销；搜索匹配→无匹配→匹配，分别采用/退出；同时送入旧草稿诊断，再继续编辑 | 未采用建议不当作草稿；搜索期间无旧诊断；返回编辑后按实际草稿恢复反馈，不等下一条命令才恢复；采用不执行，草稿/光标与基线语义一致 |
| **V06 键义与 AI 开关** | C01-C04、C12、M01-M03 | 空串、仅空白、非空草稿 × 有/无现有候选 × AI 开/关/auto off；F2/改键、Tab、Enter、取消 | 文案、事件及结果三者一致；空白 F2 不主动请求修复，带空格的非空缓冲 Ctrl+D 不误标退出；AI 禁用不关闭独立输入辅助 |

宿主结果按 Linux/macOS、Windows Terminal + WSL、原生 Windows、IDE 终端、代表性 tmux/SSH 分开记录。原生 Windows 通过独立 ConPTY CLI 回归覆盖基本绘制、编辑、补全及取消，不把它等同于全部 Windows Terminal 字体、DPI 或真实宿主历史场景的覆盖。每项保留源码版本、开关、实际列/行数、输入/结果和独立终端恢复证据。

采样需等待实际尺寸/状态事件及对应重绘，失败时再次稳定采样并追加一次编辑检查，不能用固定短延迟截图判定通过。像素截图只作辅助；验收同时读取真实终端文本/光标与应用事件结果，不能以过时的 PrintWindow 像素代替当前画面，也不能仅用 VT 模型代表真实宿主。

### 7.2 测试入口

布局、反馈和编辑器行为分别由 `nosh-shell` 的 `status`、`input_assist`、`editing` 用例覆盖，真实 Shell / Mock 交接由 `nosh-core/tests/terminal` 覆盖，CLI 的采集与状态开关由 `nosh-cli/tests` 覆盖。修补编辑器按[源码维护说明](REEDLINE-MAINTENANCE.md)独立运行测试。

实际宿主结果作为带源码、终端尺寸、配置、执行文本与恢复证据的运行产物保存，不在设计文档维护通过数量。§6 的限制未解除前，不能声称所有宿主门槛均已通过。

## 8. 非目标

沿用 #36 的分工，状态层消费能力，整合后的显示与终端兼容由本 issue 负责：

| 关联范围 | 本设计消费什么，不新增什么 |
|---|---|
| #23 编辑模式与键位、#24 补全 | 当前模式、真实候选/查询状态和有效绑定；不重做键表、候选生成/排序或慢查询治理 |
| #34 / #22 输入辅助 | 复用已有事实和 repaint，不重开一套诊断实现 |
| #27 环境与终端命令区域 | 使用已有提示符上下文，重绘不触发环境钩子或冒充新命令 |
| #18 / #30 输出与 PTY | 复用现有会话 PTY、完整尺寸和采集边界；不增加日志或新捕获链路 |
| #32 / #33 审批 | 展示实际模式、状态和选项；不改变权限策略、自动准入取舍或审批输入控件 |

不要求上述生产者为状态栏重写业务或追加整套专属验收；确实缺少状态元数据时只明确最小接口依赖，显示层不能造数据补齐。

不重做审批策略、候选生成、历史存储、任务续接、PTY 输出采集或键位配置；状态只消费实际能力，不伪造尚不存在的动作。当前不提供 GUI，也不预建跨前端框架或接口。
