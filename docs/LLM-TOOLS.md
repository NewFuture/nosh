# LLM tools 设计

原则：**Agent 的操作工具与用户输入能力分开；CommandAssist 是 nosh 发起的内部任务服务，查询后直接交付候选。** 操作工具的 schema 与执行准入共用 `BuiltinTool`／`ToolSet`，Agent 的 `ask_user` 由输入能力决定；CommandAssist 不开放终端对话。上下文选择见 [Project context](PROJECT-CONTEXT.md)。

## 工具与模式

| 工具 | 参数 | 契约 |
|---|---|---|
| `exec` | `command`，`timeout_sec?` | 从会话当前 cwd 执行 Bash 兼容代码，cwd／变量持续存在；返回 stdout／stderr 和退出状态。省略超时使用配置值（配置默认 60 秒），显式超时支持小数秒并夹取到 1–600 秒 |
| `read_file` | `path`，`start_line?`，`end_line?` | 读取带行号的文本；行号从 1 开始，起止均包含，小于 1 按 1 处理。省略 end_line 时请求到 start_line + 399；显式指定结束行也每次最多读 400 行。大输出及长行会截断；不列目录，不能解释的行号及起止冲突明确报错 |
| `grep` | `pattern`，`path?`，`glob?` | 递归搜索**文件内容**，pattern 是默认区分大小写的正则，可用 `(?i)`；glob 筛文件，不搜索文件名。返回 `path:line:text`，最多 200 行，标明不完整扫描 |
| `command_help` | `name`，`query?` | 仅 CommandAssist 使用。name 可包含子命令（如 `git commit`），受限查询帮助并返回相关原文及状态；query 忽略大小写，关键词／短语按子串匹配、选项保留名称边界，返回原文不改大小写；不是正则或程序参数 |
| `ask_user` | `question`，`choices?` | 仅 Agent 有交互输入能力时提供；可选单选建议始终允许自由输入，返回原文回答并在原会话继续，不授予执行权限 |

普通 Agent 的操作工具是 `exec`、`read_file`、`grep`；管道附件仅保留 `read_file`、`grep`。两种 Agent 模式有可用控制终端时均额外提供 `ask_user`，提问不读取 stdin，也不改变只读边界。CommandAssist Generate/Fix/Next 固定注册 `command_help`、`read_file`、`grep`，即使来自交互终端也不增加工具。三种辅助均直接向 nosh 返回完整候选命令或精确 `[None]`，不注册 `ask_user`、`command_info`、`exec` 或 `finish`。帮助查询是真实且受限的执行，详情见 [CommandAssist](COMMAND-ASSIST.md)。

模型可见描述直接说明用途和必要的动作选择：`exec` 已在当前目录运行且保留会话状态，有输入能力时缺少必要信息须用 `ask_user` 等待答复，不将问题写成最终答案。无输入能力时不要求调用不存在的提问工具；参数说明保留含义、必要默认值和简短例子。grep 的区分大小写正则及 `(?i)` 与 command_help 的字面搜索明确区分，不提前堆叠实现细节、异常情况或重复告诫。权限和扫描限额仍由宿主强制，截断、无匹配等状态在实际结果中说明。Agent 的 `ask_user` 明确单独调用、等待回答、回答不是执行审批；背景规则不把真实用户回答当作外部工具数据，回答仍可更新需求。模型目录只使用规范名称和字段，兼容别名仅供宿主接收不同写法。

**模型只看到一套简短的规范名称和字段，宿主优先兼容无歧义写法。** `ToolSpec::normalize_args`／`prepare_call` 共用于解析器和执行准入，接受大小写、snake/camel/kebab 写法、显式登记的别名、数字字符串与整数值浮点数、单元素标量数组、JSON 编码的数组，以及可选项的 null／空值。文本参数本身不去引号、不拼接多元素命令数组、不改写文件名。相同重复参数接受，转换后仍冲突的值拒绝；完全相同的选项去重，选项的数字／布尔值可原样转成显示文字，空白不同的选项仍按原文检查。`reason`／`explanation` 是可忽略的调用注释，不参与任务指令或授权；其它不能解释的操作字段不静默忽略。

字段匹配、归一化和必要约束在同一遍处理中完成，不再额外遍历整份 schema 校验。未明确声明单一类型、或明确允许 null 的字段保留原始数组／null，不把合法数据猜成单元素包装或缺省值。宿主各入口负责一次准入；提问先构造已验证的 `UserQuestion`，读取先解析当前权限 context 中的路径，再进入原有权限检查。`read_file`／`grep` 的审批与执行共用同一词法路径解析器，保留 Windows 驱动器、UNC 共享根及 verbatim 前缀，不把目标退化为当前驱动器下的同名路径。

整数字符串的十进制／指数写法按数字位精确归一化，不通过浮点舍入猜测整数；超大整数不丢失有效位，仍有非零小数的值明确拒绝。

兼容元数据使用宿主侧 `x-name-aliases`、`x-aliases`、`x-ignored-parameters`、`x-compatibility-only` 与选项标签的 `x-scalar-text`，由 `model_parameters` 移除后再渲染，不给小模型增加别名列表或备用参数。执行名称如 `run_command`／`exec_command`／`bash` 归入同一个 `exec` 权限；`file_path`／`start`／`end`、`regex`、`command_name`、`prompt`／`options` 等字段别名只在所属工具内生效，不做模糊拼写猜测。原有能力集合不扩大，CommandAssist 和只读 Agent 仍不接受执行别名。

额外接受明确单位的 `timeout_ms`，与秒字段同时提供时必须表示同一超时；不猜测无单位的其它超时字段。`cwd`／`workdir` 仅在解析后等于共享会话当前目录时接受，不能悄悄切换或恢复目录。grep 兼容 `ignore_case`／`case_sensitive`，作为正则默认大小写设置，内嵌正则旗标仍按库语义生效；相互矛盾的设置明确报错。必填内容、不能解释的值、字节／扫描预算、保护路径、审批、取消及跨字段语义仍由宿主保证。兼容不等于猜测用户意图或授予新权限。

工具定义共享规范名称和 JSON schema，调用语法按模型渲染。MiniCPM5 工具区先给出简短调用格式，再列 `<tools>` 中的完整 JSON schema：

```text
Tool calls:
<function name="function-name"><param name="param-name">param-value</param></function>
Wrap values containing <, & or newlines in <![CDATA[...]]>.
```

仅当前工具包含数组参数时追加 `Array values must be JSON, e.g. ["yes", "no"].`，让 `ask_user.choices` 的 XML 值格式明确，不给没有数组参数的 CommandAssist 增加说明。

Qwen3.5 使用 `<tool_call>` 中的 `<function=名称>` 和 `<parameter=名称>`，参数值在起止标签之间，可为 UTF-8 多行文本；数组/对象值为 JSON。它不使用 MiniCPM5 的 name 属性、CDATA 或实体反转义。Qwen 的工具/思考标记虽然被官方 tokenizer 标为 `special=false`，仍按协议控制 ID 处理；不可信正文不匹配这些 ID，普通文本中的相同字样不会打开工具流。保护控制 token 时保持原 ID 和已注册 special token 的属性，重复保护不重建匹配表。

这部分只描述语法，不包含 `[None]`、只读或执行策略，不把 CommandAssist 的限制带入 Agent。工具名称、归一化、类型校验、调用数量和宿主审批对两个模型相同；模型专属字符串解析留在 `nosh-llm`。角色和工具帧遵循各自模型协议，工具说明文字是 nosh 定制，不声称整个 prompt 与官方模板逐字相同。

CommandAssist 共用固定 System：建议而不执行、平台、查询协议、数据边界和输出约定。协议 User 是 nosh，三个意图的本次请求与上下文都放进 User 任务包；终答要求和拒绝理由也是 nosh 的 User 反馈，不重复命令或原始需求。终端用户不直接参与此子会话，Agent 的交互与权限独立保留。具体文案见 [CommandAssist](COMMAND-ASSIST.md#instructions-与-prompt)。

`exec` 描述明确共享会话的当前目录与状态持续存在，具体 shell 在会话环境中标为 `nosh (bash-compatible)`，不暗示调用系统 Bash。`command_help` 用 program 并排除 builtin／alias／function，name 说明只接受程序和可选子命令，不接受选项或 shell 代码；仍只支持通过宿主检查的外部程序，未扩大执行能力。`nosh debug gen --tools` 复用生产 `exec` schema，不另维护简化接口。

模型目录和实际执行准入统一使用 `exec`，兼容输入别名不另注册工具或改变权限名称。工具 `exec` 不等于 shell builtin `exec`：前者运行受审批约束的命令，后者替换 shell 会话，仍被禁止。主 instructions 明确通过 `exec` 执行，并禁止结束或替换会话，避免同时出现“使用 exec 工具”和“不要使用 exec”的歧义。

同目录 `cd ... &&` 前缀只是多余写法，不作为工具错误，不要求模型纠正后重提。宿主保留整条命令并照常分析、审批和执行，不移除前缀、不隐藏 OLDPWD 等真实 shell 状态变化；用户 deny 仍优先。任务总步数、重复拒绝、取消和终端交接限制不变，不维护额外的 cd 纠正计数。

`command_help(name="git commit", query="--amend")` 查询提交命令的帮助，不是筛选 Git 顶层概览。name 中的子命令独立传入 argv，不接受额外选项或 shell 代码；普通程序使用 `--help`，Git 子命令使用已知短帮助 `-h`，保留真实的 129 usage 退出码。完整调用仍须通过权限分析与用户规则，未知插件不会仅因追加帮助旗标而获得授权。

name 末尾重复的 `--help`，以及 Git 的 `-h`，可作为等价帮助写法省略后再构造固定查询；其它选项不这样处理，例如 `ls -h` 不是帮助请求。

`ask_user` 必须是回合中唯一的工具调用，避免回答前就执行依赖它的操作；明确属于 `ask_user` 的解析错误也计入此检查，畸形提问与其他调用混合时整轮不执行。问题／回答最多 4,096 bytes，可选 choices 最多 20 个互异的非空单行字符串，每项最多 512 bytes；没有默认选项。终端用上下方向键选择，直接输入任意答案（包括数字）不受选项限制；问题及交互只写 stderr。回答以 `Message::UserAnswer` 回填，正文是包含 `question`、`choices` 和原文 `answer` 的 JSON，仍按普通文本渲染为工具回复，不参与旧工具输出压缩。这样模型步骤失败后，即使自动重置会话并重放待交付回答，`yes`／`second` 等答案仍保留对应的问题与选项；不新增恢复状态机。取消／EOF 中止任务，通道故障明确失败，不伪造答案或授权。Agent 输入能力变化时重开会话，保持同一会话工具前缀稳定。

`list_dir` 已移除，不保留执行别名。目录／文件名查询用 `exec` 调用 `ls` 等命令；受限模式不因此开放执行。

失败诊断通过明确入口注入匹配的已采集输出，不为拿到已有报错而重跑命令；当前不提供额外的采集槽读取工具，见[输出采集设计](OUTPUT-CAPTURE.md)。

**`Detected external commands (non-exhaustive)` 是初始探测到的部分外部命令，不是模型工具表、完整实时清单或权限白名单。** 未列出不代表不可用，项目声明的包管理器也不证明当前可以调用。

完整 Agent 的主 system 按 `files`、`dev`、`containers`、`network`、`system`、`data` 分组显示已探测命令，省略空组；额外名称归 `other`。Rules 合并为六条通用约束：请求、会话状态、非交互／交接、破坏性操作、背景边界、证据与收尾，不复制场景禁令。

管道只读模式按实际 `ToolSet` 明确仅有 `read_file`／`grep`，不注入 shell 命令清单和执行／终端交接规则；读取保护仍由宿主执行。误把目录传给 `read_file` 时，提示使用各模式共有的 `grep` 搜索文件内容，不再建议当前模式可能没有的 `exec`。

## grep

使用 `grep-regex`、`grep-searcher` 和 `ignore`，不依赖系统 `rg`。目录扫描遵循忽略规则，跳过隐藏文件及递归遇到的链接；不跟随目录链接。显式指定普通文件不应用目录扫描的忽略／隐藏过滤，文件链接仍按真实路径审批；两种入口都跳过二进制文件。返回路径相对于搜索目录，单文件则相对于其父目录。

忽略规则发现与加载属于筛选元数据，不发起审批，直接复用 `ignore` 库的默认行为和缓存；这些内容不作为搜索结果发送给模型。进入搜索目录和读取实际文件内容仍需授权，目录授权只覆盖本次调用内的实际子树。若显式搜索 `.gitignore` 等文件的内容，它仍按普通内容读取检查权限。

最多 200 个匹配行，反馈受 6,000 字符预算限制；正向 glob 不覆盖忽略和隐藏规则。每次调用累计最多枚举 10,000 个目录条目、读取 64 MiB 文件内容，复用 `agent.command_timeout_sec` 超时，不新增配置。目录条目在收集时计数，内容经流式读取，每次底层读取最多 64 KiB；零匹配也受扫描预算约束。

目录枚举和内容读取之间检查超时与取消。达到扫描／输出上限时保留已得到的匹配，标注 `truncated=yes` 和原因；截断的零匹配只表示已扫描部分未匹配。Ctrl-C 则直接取消任务、跳过同批后续调用，不算作命令执行。检查是协作式的，不强制中断单次阻塞的文件系统操作或库内忽略元数据加载。

零匹配、截断、非法 regex/glob、路径与读取错误分别报告；“未匹配”只针对本次搜索范围，不证明整个项目不存在该内容。

## Harness 与证据

- **执行准入**：命令经过风险分析和必要审批；未知／禁用工具不执行。读取保护根或普通目录中的受保护文件均需授权，目录搜索授权仅限该次调用。
- **真实结果**：保留退出码、stdout、stderr、超时、中断和截断；不把元数据当文件内容、部分输出当完整结果、失败当成功。
- **原生观察**：每个已解析的 Agent 工具调用在处理后立即产生宿主 `agent/tool_result` 观察，绑定会话内模型轮次、调用序号与原始参数，记录状态、当前目录和回填文本；不等下一次模型请求。执行结果另记实际提交给 shell 的命令、执行目录、用户编辑／宿主重写标记、退出码、耗时及中断／截断状态。它不进入模型上下文，也不是新的模型工具。
- **未执行与未知结果**：模型反馈保留现有格式，执行前拒绝或参数纠正不冒充命令结果；机器状态独立记录，不叠加状态模板。执行器返回错误且无法取得结果时记录结果未知，不补零退出码、不声称没有副作用，并停止本任务的后续调用。`commands_run` 计入这次已提交执行的调用，不代表执行成功；执行前失败或拒绝不计入。模型收到的文本和宿主记录来自同一结果；用户答复仍保持原有 JSON 与独立来源。
- **观察故障**：记录失败会明确报错并停止后续调用，已经取得的结果仍进入待回填队列；不会为了恢复观察而重放命令。取消、交接和无工具收尾时也记录未执行的后续调用。
- **输出预算**：命令 stdout/stderr 正文共享 6,000 字符，按 Unicode 字符而非 UTF-8 字节计数，状态与省略标记另计。两流均超额时按 stdout 2/3、stderr 1/3 分配，较短流未用完的额度交给另一流；展示、日志保存条件和宿主观察共用截断判断。仅截断输出另存已采集内容，不能恢复采集阶段已经丢弃的字节。
- **输出日志**：每次保存使用独立路径，不因同进程中新建 Agent 或重复编号覆盖旧证据；写入完成后才交付路径。保存失败向用户及模型反馈明确说明，不提供无效路径，也不为此重跑已经执行的命令；原退出码和截断预览仍保留。
- 终端／密码交接由 harness 直接结束任务并交回原命令，说明可能已有部分执行；不重试、不读取密码。
- 用户拒绝审批时，模型同时收到“未执行”、审批请求的风险／触发原因，以及用户明确提供的理由（若有）。审批触发原因不冒充用户拒绝理由，不暗示换写法即可绕过拒绝。
- 相同参数、相同风险上下文的被拒调用不重复审批；再次出现时转入无工具收尾。新的用户回答可触发重新评估，但不代表批准执行；不同上下文或已获得有效授权的操作不因此被拦截。
- 预算耗尽或重复拒绝后的最后一轮使用 `ToolChoice::None`，不新增终结工具。若引擎无法提供该约束，明确失败，不静默退回仅靠提示词的收尾。

权限、超时、执行计数与交接由代码保证，不依赖 prompt 放行。模型负责理解目标、选择工具、根据证据收尾；明确任务完成即停止，缺失必要目标才澄清。

## 建议模式

建议仅接受一个完整 shell program，可为单行或完整多行结构。由 brush 检查语法与可确认的命令名；递归覆盖替换和已知函数作用域。动态无法确认不等于成功或安全，建议从不自动执行。

CommandAssist 从调用方 `AgentConfig` 构造明确权限 context，复用用户规则，不构造默认策略替代调用方配置。

## 维护与测试

工具变化需验证接口、权限、错误、过滤／截断与固定 seed 全量回归。正确率、步数、确认次数和输入成本分别报告；裁判缺陷独立处理，不用工具或 prompt 特例绕过评分。

主提示、建议提示和 `exec` 说明均以当前目录、持久会话为准；保留合法 `cd`，执行器不改写命令。无模型回归与真实模型测量分开运行，不把展示变短当作行为改善。
